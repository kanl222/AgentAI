# Ответы по документам без подсказок об источнике

21 октября 2026 года исправлен путь от естественного вопроса до ответа.
Это продолжение [проверки без подсказок](unhinted-search-evaluation.md), которая выявила
остаточные ошибки после первого исправления.

## Изменения

Новый вопрос сначала ищется по всему доступному пользователю индексу.
Контекст настоящего уточнения добавляет материалы, но больше не исключает
документы новой темы. Слово «его» в текущем предложении само по себе не
считается отсылкой к прежнему вопросу. Явно названный файл по-прежнему
ограничивает поиск по запросу пользователя.

Для вопросов без файла добавлен семантический отбор документов:

1. Из разрешённых активных фрагментов строится короткий каталог: начало
   документа и строка, наиболее близкая к текущему вопросу.
2. Та же локальная модель выбирает кандидатов группами по восемь описаний.
   Из каждой группы сохраняется до двух кандидатов; второй фильтр не
   выбрасывает их. В пилоте один длинный каталог и повторный итоговый отбор
   теряли подходящие документы.
3. Для выбранных документов читаются оригинальные фрагменты и добавляются
   к первоначальной выдаче. Описания каталога сами не являются доказательствами.
4. Варианты сокращений вроде `АБ «ВГ»` / `абвг` выводятся из самих материалов,
   без словаря под контрольные вопросы.

Модель получает только номера и описания разрешённых материалов. Выбранные
номера проверяются на принадлежность текущей группе; все чтения повторно
соблюдают ACL и активные поколения. Ошибка дополнительного отбора сохраняет
обычный поиск и отражается в `retrieval.catalog_selection`.

В проверку ответа добавлены узкие признаки ложного отказа при найденном
описании, противоречия «инструкции нет» / «вот её шаги» и числовых значений,
отрицания существующего сравнения, а также неподтверждённых попарных связей
между операциями и таблицами. Исправлено ложное приписывание следующего
пункта списка предыдущему столбцу таблицы.

Для короткого определения с явным названием в таблице возвращается точная
формулировка источника без генерации реестровых кодов и классификаций.
Упоминание известного поля проверяется по тексту процитированного фрагмента:
ссылка на соседний документ не подтверждает значение поля. Повторный неверный
адрес при наличии проверенного фрагмента с указанным полем также заменяется
цитатой. Для числовых значений различаются коды режимов и количество записей:
перечень кодов не доказывает неизвестное количество записей.

После обычной попытки исправить ответ повторное неподтверждённое отрицание
описания/сравнения, ошибка значений таблицы, неподтверждённая ссылка или
выдуманное соответствие двух списков может заменяться цитатой оригинального
фрагмента при наличии подходящих проверенных доказательств. Для списков явно указывается, что отдельные
пары не установлены. Это отмечается в `retrieval.extractive_fallback`.

## Проверка и применение

- Полный backend: **229 passed** с отдельной временной PostgreSQL.
- Проверки синтаксиса и архитектуры: 125 файлов Python, 73 модуля,
  новых циклов и нарушений зависимостей нет.
- Пилот на прежних пропусках нашёл и использовал нужные документы для
  определения ИСЛО, встроенного отчёта, аудита изменений и сведений о рецепте.
- Полный прогон первого кандидата: все 13 контрольных документов появились
  среди найденных материалов. Он также выявил ошибки содержания, для которых
  затем добавлены проверки и цитирование исходника.
- Полный прогон первого обновления работающего API: `work/natural-deployed.json`.
  Он включает 14 самостоятельных вопросов без файлов/таблиц/полей и четыре
  сообщения через настоящую очередь чата. Ожидаемые документы использует
  только оценщик; модель не получает имён источников из контрольного набора.
- Дополнительная проверка после исправлений определений и ссылок:
  `work/natural-final-live.json`: точное определение ИСЛО, правильная ссылка
  для поля всех складов, сравнение механизмов отчётов и **4/4** реплики
  HTTP-диалога с нужными источниками и разными ответами. Созданный диалог
  удалён, отсутствие подтверждено 404. Этот прогон обнаружил ещё одну
  формулировку ложного отказа по числовым кодам; она исправлена отдельно.
- Заключительная проверка числовых кодов: **1/1**,
  `work/natural-values-final.json`. Ответ правильно перечисляет
  `flag_order`: все — 1, заявлены без выписки — 2, выписаны без заявки — 3,
  без ложного утверждения об отсутствии значений.
- Прежний RAG-набор: **38/38**, Recall@3 и MRR@6 равны 1;
  результат в `work/natural-rag.json` (отдельный индекс в памяти).

API обновлён из сохранённого локального образа с теми же зависимостями.

Контрольные суммы всех 73 исполняемых файлов сверяются с локальными исходниками;
результат — `work/natural-runtime-fingerprints.json`.
Окончательная сверка успешна: все 73 файла совпали. Рабочие сервисы healthy;

## Практические ограничения

Дополнительный выбор материалов увеличивает время ответа. Каталог ограничен
48 документами, при большей базе отбирается 48 по лексической близости;
исходный гибридный поиск продолжает охватывать все разрешённые материалы.
Переиндексация и замена embeddings не требовались.

Проверки обнаруживают конкретные классы ошибок, а не доказывают истинность
каждого предложения небольшой модели. Цитирование защищает от повторения
выявленных ошибок; остальные утверждения всё ещё требуют сверки с источником.
После последних поправок полный набор 14 естественных вопросов заново
не запускался: выполнены полный backend-набор и адресные живые проверки.
Статистика наличия контрольного документа и совпадения слов в ответе не
равна независимой оценке фактической правильности.
