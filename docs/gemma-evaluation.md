# Проверка google/gemma-4-e2b — 21 октября 2026

Проверена установленная в LM Studio Gemma 4 E2B, GGUF Q4_K_M, на текущем
конвейере AgentAI. Рабочая модель в настройках не менялась. После теста
восстановлены Qwen3-4b с контекстом 8192 и одним потоком генерации и прежняя
Nomic с контекстом 2048. Наличие загруженных экземпляров проверено через
native API; AgentAI `/ready` вернул 200.

## Ответы по документам и коду

Контекст 8192, parallel=1, temperature=0, лимит генерации 2400 токенов,
MAX_STEPS=4. Прогон после отдельного короткого прогрева, на прежнем индексе
и модели embeddings. Прогрев исключён из времени сценариев. GPU резервировался
общей блокировкой AgentAI на время переключения моделей и теста.
Чаты, документы и индекс диагностическим прогоном не записывались.

| Сценарий | Результат |
| --- | --- |
| Восемь вопросов по документам, включая таблицу и два SQL | 8/8 автоматических проверок |
| Отсутствующий файл и отсутствующие SLA/серверы | 2/2, сведения не придуманы |
| Анализ сложности алгоритма | Не принят: нет конкретных оценок времени и памяти |
| Предложение рефакторинга | Проверки поведения проходят, но метод скопирован без улучшения |
| Положительный фильтр | Функция проходит независимые тесты, запрошенный нулевой случай в тестах отсутствует |

Автоматический итог: **11/13**, ошибок запросов нет. Это не оценка полной
содержательной правильности всех 11 ответов: например, копирование метода
проходит проверку сохранения поведения, но не выполняет просьбу улучшить код.
Поэтому ручная проверка остаётся обязательной.

Медиана всех сценариев — **15,291 с**. Два сценария выполняются backend без
генерации; медиана остальных 11 — **19,204 с**. Всего — 242,805 с.
В 10 ответах потребовалась дополнительная генерация после замечаний проверки.
В сценариях зарегистрировано 12 101 токен рассуждения; отдельный режим без
рассуждений не проверялся. Результаты относятся к одному прогону на данном
компьютере и текущих настройках.

Два конкретных недостатка:

- После замечания об оценке сложности модель выдала описание агрегации и
  сортировки вместо формулы времени. Раздел про память перечислил словари,
  но не дал оценки их размеров. Проверка отклонила ответ.
- В тесте с названием про ноль `+5` относится к клиенту 1, а `−5` — к клиенту 2.
  Итоги не погашаются. Это проверка положительного/отрицательного результата,
  но не нулевого. Замечание `zero_boundary_test` сохранилось после исправления.

Оба предложения Python прочитаны и исполнены отдельно в контейнерах без сети,
секретов и рабочих данных. Пройдены по пять эталонных тестов, 200 сравнений
рефакторинга с эталоном, 50 вариантов порядка равных сумм, 200 сравнений
положительного фильтра и независимый граничный случай ноль/возврат/положительный
итог. Сгенерированные тесты — два для рефакторинга и три для положительного
фильтра — также проходят. Это не доказывает запрошенное покрытие нуля:
его подтверждает независимый тест, а не тесты модели.

Метод в предложении рефакторинга совпал с исходным по AST. Код не применялся.
Тесты внутри общего блока кода исполнялись как модуль; тела тестов не менялись.

## Проверка изображений

Дополнительно выполнены два синтетических сценария через
[native API LM Studio с изображением](https://lmstudio.ai/docs/developer/rest/chat).
Они отдельны от AgentAI RAG: источник передан как изображение, без готового
извлечённого текста. Контекст 8192, лимит 2400 токенов, temperature=0;
native API загрузил модель с parallel=4, запросы выполнялись последовательно.
Эти времена не включены в основной текстовый прогон.

| Изображение | Gemma | Результат |
| --- | --- | --- |
| Русская/английская строка и число 12345 | 4,226 с | Все строки и число совпали, включая AgentAI |
| Таблица SSRS/ISLO | 7,651 с | Все четыре значения и привязки к столбцам верны; возвращён JSON |

Тот же OCR-сервис Tesseract обработал изображения за 1,031 и 0,672 с.
В первом примере он распознал AgentAI как AgentAl; во втором выдал плоский
текст с содержимым ячеек без заголовков SSRS/ISLO. Gemma в этих двух примерах
точнее сохранила обозначение и структуру по инструкции, но тест не охватывает
плохие сканы, повороты, рукопись, длинные документы или разнообразные таблицы.
Менять рабочий OCR на основании двух изображений преждевременно.

## Сравнение с Qwen и ограничения

Первый контрольный прогон Qwen оказался непригоден для сравнения: после двух
первых сценариев произошли OpenAIConnectionError и ошибки поиска/embeddings,
всего 10 ошибок запроса. CLI LM Studio также сообщил о разрыве WebSocket.
Этот результат не считается оценкой качества Qwen и не используется для
сравнения скорости. Причина нестабильности локального runtime не установлена.

После восстановления выполнен один повтор контрольного прогона Qwen:
`work/answer-evaluation-20261021-340b73da/`. Он завершён без ошибок запросов,
на тех же вопросах, с теми же настройками контекста, бюджета и генерации.
У всех 13 сценариев совпали хеши окончательных наборов доказательств
(ID, адреса и текст фрагментов), переданных конвейеру ответа.

| Метрика | Gemma 4 E2B | Qwen3-4b |
| --- | --- | --- |
| Автоматические проверки | 11/13 | 11/13 |
| Ошибки запросов | 0 | 0 |
| Медиана 11 сценариев с генерацией | 19,204 с | 3,827 с |
| Общее время 13 сценариев | 242,805 с | 114,447 с |
| Ответы с повторной генерацией | 10 | 7 |
| Токены рассуждения | 12 101 | 0 |

Обе модели не прошли анализ сложности и задание про положительный фильтр,
но причины второго отказа различаются. У Gemma отсутствует настоящий нулевой
итог в тестах. Qwen сформировала правильные нулевые данные, но вернула методы
с self вне TestCase, без законченного тестового модуля. Независимые проверки
обеих функций Qwen прошли; четыре её теста рефакторинга также прошли. Модуль
тестов положительного фильтра не обнаруживает исполнимых тестов и завершается
с кодом 5 — он не считается прошедшим. Тесты модели не исправлялись.

В этом прогоне медиана сценариев с генерацией у Gemma примерно в пять раз
выше. Это время всего конвейера с повторными генерациями и рассуждением,
а не сравнение чистой скорости декодирования. Замена Qwen на Gemma не дала
преимущества для текстового агента в данной выборке; основной оставлена Qwen.
Потенциал Gemma для чтения структуры изображения подтверждён только двумя
синтетическими примерами, а не полным OCR-бенчмарком.

Полные ответы с выдержками из рабочих документов остаются вне Git:
`work/gemma-evaluation/gemma/`, `qwen/` (неудачный контроль),
`vision/report.json`, `restored.json`, `comparison.json` и папка успешного
повторного контроля `work/answer-evaluation-20261021-340b73da/`.
В `state.json` сохранены параметры и исходное состояние: перед началом теста
модели в LM Studio не были загружены. Итоговое восстановление проверено
отдельно, включая parallel=1 у Qwen.
