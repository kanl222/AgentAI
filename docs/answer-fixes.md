# Исправления ответов и отдельный SQL-навык

Применено к рабочему API 21 октября 2026 года после проверки резервной копии.

## SQL-навык

Работа с запросами и схемами вынесена в `skills/sql/SKILL.md`. Backend выбирает
его до первой генерации для SQL, JOIN, схемы БД и запросов, подтверждённых
SQL-примером в найденном источнике. Обычный запрос API не считается SQL-задачей.
Для исходного кода остаётся `code`, для фактов из документов — `documents`.
Модель может подключить дополнительный навык через `load_skill`.

Навык требует сохранять диалект, таблицы, поля и JOIN; проверять агрегирование,
NULL и границы периода; параметризовать входные значения по запросу пользователя;
не угадывать назначение сокращений и не считать пустой AS описанием поля.
Запрос оформляется отдельно от ссылок, а неполнота схемы указывается явно.

`database_schema` по-прежнему доступен только роли `sql_reader` и читает
метаданные SQL Server. Навык не добавляет полномочий и инструмента исполнения
произвольного SQL. Ответ содержит предложение запроса, а не утверждение,
что запрос выполнен или проверен на реальной медицинской базе.

## Изменения подготовки ответа

- Выбранный документ сохраняется в продолжении диалога независимо от длины
  вопроса и наличия слова из короткого списка. Новый явно названный документ
  или фраза «Другая тема»/«Новый вопрос» сбрасывает прежнюю область. Имя
  выбранного файла остаётся в поисковом запросе и на третьем ходе.
- Backend подключает основной навык перед генерацией, поэтому соблюдение
  этого шага больше не зависит от вызова `load_skill` моделью.
- В модель передаются метки ref и координаты фрагмента вместо готового адреса
  с UUID версии. Точные адреса формируются из сохранённых доказательств.
  Повторный завершающий список Sources удаляется перед оформлением сервером.
- Для отсутствующего явно названного документа/символа ответ формируется
  до генерации: источник не найден среди доступных материалов.
- Проверяются синтаксис Python, тесты с self вне TestCase, изменение ключа
  сортировки и пропуск вложенного обхода/сортировки в оценке сложности.
  При явном требовании стабильного порядка простой чистый ключ сортировки
  может быть восстановлен из исходника; неоднозначные изменения отклоняются.
- Неподтверждённая подпись поля SQL удаляется, только если источник содержит
  пустой AS и от подписи не зависят другие ссылки в запросе. Строки и комментарии
  не переписываются. Если безопасное исправление неоднозначно, ответ получает
  замечание проверки.
- Замечания проверки сохраняются после дополнительного чтения источника.
  Отклонённый ответ не повторяется как образец для исправления. В замечания
  не включается вторая обрезанная копия уже доступного источника: она вызывала
  повторные чтения и исчерпание лимита шагов.
- При просьбе ограничиться анализом скопированный метод и осиротевшие
  разделители блока кода удаляются, чтобы не скрывать ссылки внутри блока.

Полученные предложения Python исполнялись в отдельных контейнерах без сети,
секретов и рабочих данных. Пройдены пять эталонных тестов, 200 сравнений
метода с эталоном, 50 вариантов равных сумм, 200 сравнений положительного
фильтра и отдельная проверка нуля/возврата/положительного итога. Четыре
сгенерированных теста каждого предложения также прошли.

Основной прогон на модели дал 12 принятых ответов из 13. Ответ с оценкой
сложности продолжает давать пропущенный или неверно учтённый вложенный обход
и отклоняется проверкой. Позднейшие повторы этого случая также не считаются
успешными. Не следует считать ссылку или статическую проверку доказательством
корректности любой оценки сложности и любого предложенного теста.
В сгенерированных тестах положительного фильтра название про ноль не
гарантировало наличие нулевого итога; сам ноль проверен независимым тестом.

## Рабочая среда и восстановление

После прерывания Docker был остановлен, модели выгружены. Сервисы восстановлены.
Загружены прежние Qwen и Nomic; пространство embeddings не менялось. У Qwen
контекст 8192 и один поток генерации, соответствующий последовательной очереди
AgentAI. Предшествующие ошибки LM Studio (`Channel Error`, `Model does not exist`)
не считаются успешными ответами и сохранены в промежуточных отчётах.

Перед обновлением: `backups/answer-fixes-20261021-70201ed6`. Проверены
восстановление PostgreSQL в отдельную базу, восстановление 206 точек Qdrant
в отдельный сервис и SHA256 всех 34 оригиналов. В manifest сохранён тег
предыдущего образа API. Переиндексация для этих исправлений не требовалась.

Повторить основные вопросы:

```powershell
.venv\Scripts\python.exe scripts/run_answer_evaluation.py
```

Внутри API можно запускать отдельные сценарии:

```powershell
docker compose exec -T api python scripts/evaluate_answers.py --case doc-7 --case doc-8 --output /tmp/sql-check.json
```

Ненулевой код завершения означает ошибку запроса или замечание автоматической
проверки. Сохранённые отчёты всё равно требуют проверки по исходникам.
