## Изменения

- `answering/validation.py`: номера таблиц, строк и страниц исключаются из
  кандидатов на значения поля. Остальная часть высказывания продолжает
  проверяться, поэтому настоящее противоречие не скрывается. Отрицание
  «а не DefaultController» и явно обозначенный ошибочный предыдущий ответ
  больше не считаются текущими положительными утверждениями.
- `answering/complexity.py`: выделенная проверка обнаруживает общую оценку
  без I при определении I как общего числа позиций, повторное начисление
  O(I) на каждый заказ и отсутствие оценки дополнительной памяти.
  Заголовок со словом «память» сам по себе оценкой не считается.
- `answering/test_boundaries.py`: ограниченный статический разбор простых
  Python-тестов связывает литеральные входы с вызовом запрошенной функции
  и проверкой пустого результата. Ноль и отрицательный итог вычисляются
  по данным, а не по имени теста. Пустой вход, неизвестный клиент,
  другая функция и положительный ожидаемый результат не подтверждают ноль.
  Поддержаны Decimal, переменная результата, unittest и простой assert ==.
- `answering/engine.py`: повторная генерация сохраняет объём исходного
  запроса и выдаёт окончательный ответ без пересказа ошибочных вариантов.
  Убрано безусловное требование блоков кода при исправлении ответа,
  в том числе когда пользователь просил только анализ.

Проверка входов не выполняет код модели, не вызывает функции из ответа
и не предоставляет новых инструментов. Неизвестные выражения и ветвления
считаются непроверенными. Она намеренно ограничена примером обработки
заказов с полями customer_id/items/price/quantity и запросом о фильтре
строго положительного итога. Это не универсальное доказательство покрытия
произвольных тестов. Аналогично проверка сложности выявляет отдельные
противоречия, но не доказывает произвольную асимптотику.

Для текущего алгоритма корректная верхняя оценка времени —
O(C + N + I + U log U), дополнительной памяти — O(C + U), где C — число
входных записей клиентов, N — число заказов, I — общее число позиций,
U — число накопленных итогов. Это обычная оценка при постоянной стоимости
операций Decimal и ожидаемой постоянной стоимости операций словаря.
Для другой реализации формулу нужно выводить заново по её исходникам.
