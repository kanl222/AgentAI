# Настройка RAG

Настройки применены к рабочему API 21 октября 2026 года. Переиндексированы
25 актуальных сохранённых документов: опубликованы 83 фрагмента. Оригиналы,
версии, метаданные, история и задания сохранены. Прежние поколения векторов
остаются в хранилище, но исключены из поиска.

## Конвейер и параметры

Извлечение PDF/DOCX/TXT/MD → фрагменты с координатами источника → локальные
embeddings → Qdrant. Поиск объединяет dense и BM25 через RRF, проверяет права
и активные поколения, передаёт найденные фрагменты модели вместе со ссылками.

Значения задаются в `.env`, образец — `.env.example`. После изменения нужен
перезапуск API через `docker compose up -d --no-deps api`.

| Переменная | По умолчанию | Назначение |
| --- | ---: | --- |
| `RAG_CHUNK_CHARS` | 3500 | Максимальная длина фрагмента в символах |
| `RAG_CHUNK_OVERLAP` | 400 | Перекрытие соседних фрагментов, 0 отключает |
| `RAG_CHUNK_LINES` | 50 | Максимальный диапазон строк фрагмента |
| `RAG_CANDIDATES` | 20 | Кандидаты от каждого способа поиска |
| `RAG_TOP_K` | 6 | Число результатов после объединения |
| `RAG_CONTEXT_CHARS` | 12000 | Бюджет сериализованных источников для модели |

Перекрытие ограничено четвертью длины фрагмента и пятой частью лимита строк.
При переходе между страницами PDF, абзацами и строками таблиц DOCX перекрытия
нет: сохраняются их отдельные координаты. При разрезании длинной строки
цитата указывает исходную строку, текст может содержать только её часть.
Изменение параметров фрагментов требует повторной индексации документа;
изменение глубины поиска и бюджета контекста — только перезапуска API.
Внутренние ограничения не позволяют задать бесконечные размеры и глубину.

Число кандидатов фактически не меньше `RAG_TOP_K`. RRF сохраняет прежнюю
константу 60 и равные веса; новые веса без сравнительного теста не вводились.
Кеши и ограничения доступа работают независимо от этих параметров.
При настройке следует учитывать [рекомендации Qdrant по сравнению вариантов
fusion](https://qdrant.tech/documentation/search-tuning/how-to-tune-hybrid-search/).

## Проверка качества

Повторяемая проверка с текущей локальной моделью embeddings:

```powershell
docker compose exec -T api python scripts/evaluate_rag.py --dataset examples/rag-regression.json --output /tmp/rag-evaluation.json
docker compose exec -T api cat /tmp/rag-evaluation.json
```

Скрипт берёт общую блокировку GPU и создаёт отдельный индекс в памяти.
Рабочий индекс и диалоги не меняются. Если GPU занят запросом, проверку
следует повторить после его завершения.

Набор содержит 30 базовых запросов, четыре факта на границе фрагментов,
три проверки пустой или запрещённой области поиска и строку таблицы.
`expected_text` требует наличия факта целиком в одном найденном фрагменте,
а не только совпадения документа. `expected: null` проверяет пустую выдачу
для отсутствующего файла или недоступной области; это не проверка отказа
модели отвечать на любой вопрос без оснований.

| Метрика на 38 синтетических случаях | Без перекрытия | С перекрытием |
| --- | ---: | ---: |
| Пройденные проверки | 34/38 | 38/38 |
| Recall@3, 35 положительных случаев | 0,886 | 1,000 |
| MRR@6, 35 положительных случаев | 0,886 | 1,000 |

Использована `text-embedding-nomic-embed-text-v1.5`; одинаковые тексты
и запросы в обоих вариантах получили одни и те же сохранённые векторы.
Детали локального сравнения: `work/rag-comparison.json`. Четыре исправления
относятся к совместному присутствию связанных фактов в одном фрагменте.
Этот набор не измеряет качество произвольных ответов или реальную точность
на всех документах организации. Полный набор проверок backend: 131 passed.

## Embeddings и ограничения

Модель embeddings, размерность и обработка входного текста сохранены.
Nomic [рекомендует префиксы `search_document:` и `search_query:`](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5).
Их добавление требует отдельной проверки поведения LM Studio и согласованной
миграции всего пространства embeddings, включая индекс исходного кода.
Частичное добавление префикса только к новым запросам или документам
создало бы несогласованный индекс. В этой настройке такой миграции нет.

PDF без текстового слоя обрабатывает отдельный [OCR-сервис](ocr.md).
Бюджет контекста считается в символах,
а лимит модели — в токенах: увеличение бюджета не гарантирует, что длинный
диалог поместится в окно модели. Ссылки и проверки фактов не гарантируют
истинность каждого предложения сгенерированного ответа.

## Резервная копия

Перед переиндексацией API был остановлен после завершения очереди.
Копия: `backups/rag-20261021-e05bebfb`. PostgreSQL восстановлен в отдельную
тестовую базу; snapshot Qdrant восстановлен в отдельный сервис и проверены
123 точки. Проверены SHA256 всех 34 сохранённых оригиналов. В manifest
сохранены контрольные суммы и тег предыдущего образа API.

Переиндексация публикует каждый документ новым поколением после полной
записи его векторов. Для возврата всего состояния нужно согласованно
восстановить PostgreSQL и Qdrant из одной копии, затем запустить сохранённый
образ. Один возврат образа API не возвращает предыдущие поколения индекса.
