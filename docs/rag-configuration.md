# Настройка RAG

Актуализировано 22 октября 2026 года. Поиск переведён на Qwen3-Embedding-0.6B
Q8_0 на CPU: 32 документа, 96 активных фрагментов, новая коллекция с размерностью
1024. [Перенос и проверки](qwen-embedding-migration-20261022.md).
Предыдущее [исправление поиска и ответов](natural-retrieval-fix.md) сохранено.

При первоначальной настройке 21 октября были переиндексированы
25 актуальных сохранённых документов: опубликованы 83 фрагмента. Оригиналы,
версии, метаданные, история и задания сохранены. Прежние поколения векторов
остаются в хранилище, но исключены из поиска.

## Конвейер и параметры

Извлечение PDF/DOCX/TXT/MD → фрагменты с координатами источника → локальные
embeddings → Qdrant. Поиск объединяет dense и BM25 через RRF, проверяет права
и активные поколения. Новый вопрос сначала ищется независимо от прежней темы;
настоящее уточнение дополнительно использует контекст истории. Явный файл или
идентификатор задаёт область поиска.

Для самостоятельных вопросов без явного источника добавляется семантический
отбор: до 48 описаний разрешённых документов, группы по 8, до 2 кандидатов
каждой группы. При большем корпусе каталог ограничивается лексической близостью,
но первоначальный гибридный поиск охватывает весь разрешённый корпус.
Оригинальные фрагменты выбранных документов объединяются с первичной выдачей
до 12 результатов. Поэтому `RAG_TOP_K` — глубина исходного гибридного поиска,
а не предел итогового списка после расширения. Бюджет контекста сохраняется.
Для явного источника и контекстного уточнения дополнительный отбор не запускается.

Короткое структурированное определение может выдаваться прямо из источника.
В остальных случаях найденные фрагменты передаются модели с проверяемыми
ссылками. После одной попытки исправления некоторые повторные ошибки заменяются
точной цитатой. Дополнительные вызовы модели увеличивают задержку ответа.
Размер каталога и группы сейчас задаются кодом, отдельной настройки `.env` нет.

Значения задаются в `.env`, образец — `.env.example`. После изменения нужен
перезапуск API через `docker compose up -d --no-deps api`.

| Переменная | По умолчанию | Назначение |
| --- | ---: | --- |
| `RAG_CHUNK_CHARS` | 3500 | Максимальная длина фрагмента в символах |
| `RAG_CHUNK_OVERLAP` | 400 | Перекрытие соседних фрагментов, 0 отключает |
| `RAG_CHUNK_LINES` | 50 | Максимальный диапазон строк фрагмента |
| `RAG_CANDIDATES` | 20 | Кандидаты от каждого способа поиска |
| `RAG_TOP_K` | 6 | Число результатов после объединения |
| `RAG_CONTEXT_CHARS` | 12000 | Бюджет сериализованных источников для модели |

Перекрытие ограничено четвертью длины фрагмента и пятой частью лимита строк.
При переходе между страницами PDF, абзацами и строками таблиц DOCX перекрытия
нет: сохраняются их отдельные координаты. При разрезании длинной строки
цитата указывает исходную строку, текст может содержать только её часть.
Изменение параметров фрагментов требует повторной индексации документа;
изменение глубины поиска и бюджета контекста — только перезапуска API.
Внутренние ограничения не позволяют задать бесконечные размеры и глубину.

Число кандидатов фактически не меньше `RAG_TOP_K`. RRF сохраняет прежнюю
константу 60 и равные веса; новые веса без сравнительного теста не вводились.
Кеши и ограничения доступа работают независимо от этих параметров.
При настройке следует учитывать [рекомендации Qdrant по сравнению вариантов
fusion](https://qdrant.tech/documentation/search-tuning/how-to-tune-hybrid-search/).

## Проверка качества

Повторяемая проверка с текущей локальной моделью embeddings:

```powershell
docker compose exec -T api python scripts/evaluate_rag.py --dataset examples/rag-regression.json --output /tmp/rag-evaluation.json
docker compose exec -T api cat /tmp/rag-evaluation.json
```

Скрипт берёт общую блокировку GPU и создаёт отдельный индекс в памяти.
Рабочий индекс и диалоги не меняются. Если GPU занят запросом, проверку
следует повторить после его завершения.

Набор содержит 30 базовых запросов, четыре факта на границе фрагментов,
три проверки пустой или запрещённой области поиска и строку таблицы.
`expected_text` требует наличия факта целиком в одном найденном фрагменте,
а не только совпадения документа. `expected: null` проверяет пустую выдачу
для отсутствующего файла или недоступной области; это не проверка отказа
модели отвечать на любой вопрос без оснований.

| Метрика на 38 синтетических случаях | Без перекрытия | С перекрытием |
| --- | ---: | ---: |
| Пройденные проверки | 34/38 | 38/38 |
| Recall@3, 35 положительных случаев | 0,886 | 1,000 |
| MRR@6, 35 положительных случаев | 0,886 | 1,000 |

В этом предыдущем эксперименте использована `text-embedding-nomic-embed-text-v1.5`; одинаковые тексты
и запросы в обоих вариантах получили одни и те же сохранённые векторы.
Детали локального сравнения: `work/rag-comparison.json`. Четыре исправления
относятся к совместному присутствию связанных фактов в одном фрагменте.
Этот набор не измеряет качество произвольных ответов или реальную точность
на всех документах организации. Число 131 passed относится к этапу настройки
фрагментов. На том этапе полный backend-набор: **229 passed**; прежний синтетический
поиск повторно прошёл **38/38**. Это разные виды проверок.

## Проверка вопросов без подсказки источника

`scripts/evaluate_unhinted_search.py` содержит 14 самостоятельных вопросов
и диалог из четырёх смен тем. Имена ожидаемых документов используются только
оценщиком. В отличие от `evaluate_answers.py`, вопросы не дополняются именем
нужного файла. Скрипт измеряет исходный поиск отдельно от итоговых ответов;
наличие документа и совпадение слов не доказывают фактическую правильность.

Из корня проекта в PowerShell можно передать текущий скрипт работающему API:

```powershell
$agentaiApiContainer = docker compose ps -q api
docker cp scripts/evaluate_unhinted_search.py "${agentaiApiContainer}:/tmp/evaluate_unhinted_search.py"
docker compose exec -T api python /tmp/evaluate_unhinted_search.py --output /tmp/unhinted-evaluation.json
New-Item -ItemType Directory -Force work | Out-Null
docker cp "${agentaiApiContainer}:/tmp/unhinted-evaluation.json" work/unhinted-evaluation-latest.json
```

Проверка использует существующие локальные модели, права настроенного читателя
и общую блокировку GPU. По умолчанию создаёт временный диалог через HTTP-очередь,
после проверки удаляет его вместе с заданиями; результат удаления записывается
в отчёт. Документы и индекс не меняет. `--skip-conversation` отключает запись
диалога; `--conversation-only` оставляет только исходный поиск и HTTP-диалог.
`--case overview` выбирает самостоятельный вопрос (можно повторить параметр);
состав четырёх реплик диалога этим параметром не меняется.

Диагностика результата `/chat`: `retrieval.catalog_selection` принимает
`not_needed`, `completed`, `unavailable`; при сбое дополнительного отбора
обычная выдача сохраняется. `retrieval.extractive_fallback` указывает на
замену пересказа цитатой. Также проверяйте `validation`, `used_sources` и сам
источник. Сравнение с прежним состоянием и ограничения — в
[текущем отчёте](natural-retrieval-fix.md).

## Embeddings и ограничения

Текущая модель — Qwen3-Embedding-0.6B Q8_0, 1024 измерения, окно 4096 токенов.
Отдельный сервис `embeddings` запускается только на CPU. Адрес, модель и
инструкция задаются через `EMBED_*` в `.env`. Для вопроса адаптер формирует
`Instruct: <инструкция>\nQuery:<вопрос>`; фрагменты документов остаются без префикса.
Это соответствует [карточке Qwen](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B).

Все активные фрагменты перенесены в `agentai_qwen3_embedding_0_6b`; прежняя
коллекция `agentai` с Nomic сохранена. Смешивать векторы разных моделей нельзя.
Порядок миграции и ограничения отката — в [отчёте](qwen-embedding-migration-20261022.md).
Ранее приведённые измерения Nomic относятся к прежнему индексу.

PDF без текстового слоя обрабатывает отдельный [OCR-сервис](ocr.md).
Бюджет контекста считается в символах,
а лимит модели — в токенах: увеличение бюджета не гарантирует, что длинный
диалог поместится в окно модели. Ссылки и проверки фактов не гарантируют
истинность каждого предложения сгенерированного ответа.

## Резервная копия

Перед переиндексацией API был остановлен после завершения очереди.
Копия: `backups/rag-20261021-e05bebfb`. PostgreSQL восстановлен в отдельную
тестовую базу; snapshot Qdrant восстановлен в отдельный сервис и проверены
123 точки. Проверены SHA256 всех 34 сохранённых оригиналов. В manifest
сохранены контрольные суммы и тег предыдущего образа API.

Переиндексация публикует каждый документ новым поколением после полной
записи его векторов. Для возврата всего состояния нужно согласованно
восстановить PostgreSQL и Qdrant из одной копии, затем запустить сохранённый
образ. Один возврат образа API не возвращает предыдущие поколения индекса.
