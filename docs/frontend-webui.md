> Это сохранённый старый интерфейс. Новый чат находится в `web/chat` на порту 3000; консоль API — в `web/api-console` на порту 8000. Open WebUI запускается отдельно с профилем `legacy-webui` на порту 3001.

# Установка frontend Open WebUI для AgentAI

В этом проекте Open WebUI находится в папке `frontend` и собирается локально.
Версия в `frontend/package.json` — `0.6.43`. Сервис `webui` из корневого
`compose.yaml` использует `frontend/Dockerfile` и создаёт образ `open-webui:local`.

Контейнер включает две части Open WebUI: интерфейс Svelte и собственный сервер
WebUI на Python. Сервер WebUI отвечает за вход, пользователей и историю своего
интерфейса, а за ответами агента обращается к отдельному серверу AgentAI.

```text
Браузер :3000 → Open WebUI → AgentAI :8000 → LM Studio
                              ├─ PostgreSQL
                              └─ Qdrant
```

Не путайте сервер WebUI из `frontend/backend` и сервер агента из `src/agentai`.
Для полноценной работы интерфейса нужны оба.

## Требования

- Docker Desktop запущен, снят с паузы и использует Linux-контейнеры.
- Настроены WSL2 и доступ в интернет для первой сборки.
- LM Studio доступна по адресу из `LMSTUDIO_BASE_URL`.
- Корневой `.env` настроен по инструкции основного README.

Для Docker-установки Node.js и Python на Windows устанавливать отдельно не нужно:
сборка выполняется внутри контейнеров. Если Docker Desktop поставлен на паузу,
возобновите работу через его Dashboard или меню значка Docker.

## 1. Подготовить конфигурацию

В PowerShell перейдите в корень проекта:

```powershell
cd D:\Source\AgentAI
```

При первой установке скопируйте `.env.example` в `.env`. Существующий рабочий
`.env` не перезаписывайте. Заполните как минимум:

- `AGENT_USERS` — записи пользователей с хешами ключей, ролями и источниками.
- `WEBUI_READER_KEY` — исходный ключ разрешённого пользователя с ролью `reader`.
- `WEBUI_SECRET_KEY` — отдельный случайный секрет WebUI.
- `POSTGRES_PASSWORD` — случайный пароль PostgreSQL.
- `LMSTUDIO_BASE_URL`, `LMSTUDIO_API_KEY`, `CHAT_MODEL`, `EMBED_MODEL`.

Создание ключей и записей описано в основном README. `WEBUI_READER_KEY` должен
совпадать с ключом пользователя, чей SHA256 находится в `AGENT_USERS`.
Ключ с правом загрузки документов не используйте как общий ключ WebUI.

## 2. Собрать и запустить

При первой установке:

```powershell
docker compose --profile legacy-webui up -d --build postgres qdrant api webui
```

Если сервер AgentAI и базы уже работают, достаточно:

```powershell
docker compose --profile legacy-webui up -d --build webui
```

Проверка состояния и журнала:

```powershell
docker compose ps
docker compose logs --tail 100 webui
```

Откройте <http://localhost:3001>. API AgentAI доступен по адресу
<http://localhost:8000/docs>, библиотека документов — <http://localhost:8000/library>.

Команды выполняются из корня проекта, а не из `frontend`. Корневой Compose
сам выбирает нужный Dockerfile и передаёт настройки подключения.

## 3. Создать администратора и подключить агента

1. При первой установке создайте учётную запись администратора WebUI.
2. В административных настройках подключений проверьте адрес `http://api:8000/v1`.
3. Укажите ключ из `WEBUI_READER_KEY` и проверьте соединение.
4. Выберите модель `local-agent`; отображаемое название может быть
   «Агент организации», если оно задано в WebUI.
5. Отключите потоковую выдачу для этой модели и подключение Ollama.
6. После создания администратора отключите регистрацию в WebUI и установите
   `ENABLE_SIGNUP: "false"` в корневом `compose.yaml`, затем пересоздайте `webui`.

Внутри Docker имя `api` обозначает контейнер AgentAI. Адрес `localhost:8000`
в настройках контейнера WebUI указывал бы на сам контейнер WebUI, а не на AgentAI.
Адрес LM Studio задаётся серверу AgentAI отдельно; прямое подключение WebUI
к LM Studio обходит поиск, навыки и права доступа AgentAI.

Сохранённые настройки WebUI могут иметь приоритет над окружением. Если после
смены ключа соединение не работает, обновите и сохранённый ключ в интерфейсе.

## Что скачивается при первой сборке

По текущему `frontend/Dockerfile` сборка загружает:

- базовые образы Node.js 22 и Python 3.11;
- зависимости интерфейса через `npm ci --force`;
- Pyodide и пакеты для браузерного Python через `npm run pyodide:fetch`;
- Python-зависимости сервера WebUI, включая PyTorch;
- модель эмбеддингов `sentence-transformers/all-MiniLM-L6-v2`;
- Whisper `base` для распознавания речи и данные токенизатора.

Суммарная загрузка может превышать 1 ГБ. Точный объём зависит от кеша и версий.
Эта сборка не скачивает Qwen из LM Studio. Наличие встроенной модели эмбеддингов
WebUI не означает, что AgentAI её использует: AgentAI обращается к `EMBED_MODEL`
через LM Studio.

Как читать вывод сборки:

| Строка | Что загружается |
| --- | --- |
| `Pulling`, `Downloading`, `Extracting` | Слои Docker-образов |
| `npm ci`, `pyodide:fetch` | Пакеты интерфейса и браузерного Python |
| `pip install`, `uv pip install`, `torch` | Зависимости сервера WebUI |
| `model.safetensors`, `pytorch_model.bin` | Веса модели |

Обычный повторный запуск использует существующий образ и кеш. Изменение
зависимостей, очистка кеша или сборка с `--no-cache` могут вызвать повторную
загрузку. В локальном Dockerfile `USE_SLIM=true` пропускает предзагрузку моделей,
но не исключает установку PyTorch и всего остального набора зависимостей;
это не гарантия маленького образа.

## Обновление интерфейса

После правки файлов в `frontend`:

```powershell
cd D:\Source\AgentAI
docker compose --profile legacy-webui up -d --build --no-deps webui
```

Для обычного запуска уже собранной установки:

```powershell
docker compose up -d
```

Учётные записи, настройки и история WebUI хранятся в томе `webui`.
Пересборка образа этот том не удаляет. **Не выполняйте `docker compose down -v`,
если нужно сохранить данные:** команда удаляет именованные тома проекта.
Не меняйте `WEBUI_SECRET_KEY` при каждой пересборке.

## Разработка интерфейса без пересборки контейнера

Этот режим необязателен. Установите Node.js 22 и используйте npm с lock-файлом.
В `package.json` разрешены версии Node от 18.13.0 до 22.x; Docker использует 22.
Для установки зависимостей применяется тот же режим, что в Dockerfile:

```powershell
cd D:\Source\AgentAI\frontend
npm ci --force
npm run dev
```

`npm run dev` сначала подготавливает Pyodide, поэтому также может скачивать
пакеты. Адрес Vite будет напечатан в консоли, обычно это <http://localhost:5173>.

В режиме разработки `frontend/src/lib/constants.ts` обращается к серверу
WebUI по адресу `http://localhost:8080`. Это сервер WebUI, а не AgentAI :8000.
Чтобы подключить Vite к контейнеру, создайте в корне проекта дополнительный
`compose.frontend-dev.yaml`:

```yaml
services:
  webui:
    ports:
      - "127.0.0.1:8080:8080"
    environment:
      CORS_ALLOW_ORIGIN: "http://localhost:5173;http://localhost:3001"
```

Запустите из корня:

```powershell
docker compose -f compose.yaml -f compose.frontend-dev.yaml up -d webui
```

Дополнительный файл добавляет локальный порт 8080 и разрешённый адрес Vite.
Если Vite выбрал другой порт, скорректируйте CORS. После разработки вернитесь
к обычному `docker compose up -d webui`. Не открывайте отладочный интерфейс
внешней сети без отдельной настройки доступа.

Проверки frontend:

```powershell
cd D:\Source\AgentAI\frontend
npm run check
npm run build
```

`npm run build` собирает интерфейс, но само по себе не запускает Python-сервер
WebUI. Эти команды могут обнаружить ошибки текущих исходников; наличие инструкции
не означает, что сборка frontend уже проверена в вашей среде.

## Если установка не работает

| Симптом | Проверка |
| --- | --- |
| `Docker Desktop is manually paused` | Возобновите Docker Desktop |
| Страница :3000 недоступна | `docker compose ps` и журнал `webui` |
| Долгая загрузка при сборке | Название текущего пакета/слоя, интернет и свободное место |
| Пустой список моделей | API работает, адрес подключения `http://api:8000/v1`, ключ совпадает |
| 401 или 403 | Хеш ключа, роль `reader` и доступные источники в `AGENT_USERS` |
| Ошибка Ollama :11434 | Отключите Ollama в сохранённых настройках WebUI |
| Vite работает, но вход недоступен | Доступен ли сервер WebUI на :8080 и разрешён ли CORS |
| Изменения интерфейса не видны | Пересоберите сервис `webui`, затем обновите страницу без кеша |

Перед передачей журналов удаляйте токены, ключи и закрытые данные организации.
