# Переход на Qwen embeddings — 22 октября 2026

Поиск переведён с Nomic на **Qwen3-Embedding-0.6B Q8_0**, выполняющийся только
на CPU в отдельном сервисе `embeddings`. Диалоговая Qwen3 4B остаётся в LM Studio.
Перенесены 32 документа и 96 активных фрагментов. Идентификаторы, текст,
метаданные и поколения публикации сохранены; исходная коллекция не изменена.

## Конфигурация

```dotenv
EMBED_MODEL=qwen3-embedding-0.6b
EMBED_BASE_URL=http://embeddings:8080/v1
EMBED_API_KEY=local-embeddings
EMBED_QUERY_INSTRUCTION=Given a web search query, retrieve relevant passages that answer the query
QDRANT_COLLECTION=agentai_qwen3_embedding_0_6b
```

В Compose: четыре CPU, максимум 2 ГБ RAM, один слот, 4096 токенов,
параметры `-ngl 0 --device none`, pooling `last`, 1024 измерения.
Образ llama.cpp `server-b11669` закреплён digest в `compose.yaml`.
Модель закреплена ревизией `370f27d7550e0def9b39c1f16d3fbaa13aa67728`
из [официального GGUF-репозитория Qwen](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B-GGUF).
Размер файла — 639150592 байта, SHA256:
`06507c7b42688469c4e7298b0a1e16deff06caf291cf0a5b278c308249c3e439`.

Сервис доступен внутри сети Compose, порт на хост не опубликован.
`EMBED_API_KEY` локального сервиса — условное значение: сервер запущен без
проверки ключа. При использовании внешнего embedding API задайте его настоящий ключ.
Сервис работает независимо от настроек GPU и контекста диалоговой модели.

Согласно [инструкциям модели](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B),
документы векторизуются без префикса, а вопросы получают
`Instruct: <инструкция>\nQuery:<вопрос>`. Встроенный поиск делает это автоматически.
Универсальный `POST /v1/embeddings` передаёт текст как есть: он не определяет,
отправил клиент документ или поисковый вопрос.

## Обновление существующей установки

Сначала сохраните резервную копию PostgreSQL, Qdrant и настроек; дождитесь
завершения заданий. Не допускайте загрузок и других записей в индекс до конца
переключения. Миграция рассчитана на остановку записывающего API, а не на
одновременное обслуживание старого и нового индексов.

1. Выполните `python scripts/download_embedding_model.py`. Скрипт проверяет размер
   и SHA256; повторный запуск использует уже проверенный файл.
2. Соберите новый API: `docker compose build api`.
3. Запустите CPU-сервис: `docker compose up -d embeddings`; дождитесь `healthy`.
4. Остановите API: `docker compose stop api`.
5. Укажите приведённые выше параметры в существующем `.env`, сохранив остальные
   настройки и ключи. Новое имя коллекции обязательно: векторы Nomic и Qwen несовместимы.
6. Выполните перенос:

   ```powershell
   docker compose run --rm --no-deps -T api python /app/scripts/migrate_embeddings.py --source agentai --target agentai_qwen3_embedding_0_6b
   ```

7. Проверьте итоговый JSON, число документов и `source_unchanged: true`.
   Скрипт отклоняет существующую целевую коллекцию, проверяет полноту векторов,
   неизменность исходника и поколений, совпадение идентификаторов и метаданных.
   При ошибке переключаться нельзя; частичную целевую коллекцию нужно отдельно
   проверить и удалить либо выбрать новое имя для повторной попытки.
8. Запустите API: `docker compose up -d --no-deps --no-build api`.
   Проверьте авторизованный `/ready`, реальный embedding-запрос и вопросы по документам.

На новой установке перенос не нужен: после скачивания модели обычный запуск
Compose и первая загрузка документов создают новый индекс.

## Результат переноса

Коллекция `agentai`: 206 точек, из них 96 активных; 768 измерений, сохранена
для возможного отката. Остальные точки — прежние поколения, исключённые из поиска.
Коллекция `agentai_qwen3_embedding_0_6b`: 96 точек, 1024 измерения.
Контрольная сумма отсортированных идентификаторов и payload до и после:
`186b48c0c7286c89485f2e240c75d5851c9b69391e8f29a031fae7a7177b9684`.
Оригиналы и состояния версий в PostgreSQL не изменялись.

Для отката остановите записи, восстановите прежние `EMBED_*`,
`QDRANT_COLLECTION=agentai` и предыдущий образ API, затем проверьте готовность.
Старый индекс — снимок момента переноса: новые загрузки, изменения или удаления
после переключения потребуют отдельного согласования с ним. Автоматической
двойной записи нет; нельзя просто переключить устаревшую коллекцию при изменённых поколениях.

## Основание выбора и ограничения

На локальном корпусе из 96 фрагментов проведён CPU-эксперимент с 18 вопросами,
без указания системе источника: Nomic + BM25 нашёл контрольный документ в
10/18 случаев, Qwen + BM25 — в 17/18. Медианы поиска — около 0,11 и 0,17 с
соответственно. Это измерения отдельного нативного стенда Windows с шестью
потоками, а не обещание задержек контейнера с четырьмя CPU.

Сравнение reranking не завершено: проверены только 14 вопросов Nomic, ветка
Qwen с reranking не запускалась. Поэтому reranker в рабочую систему не включён,
полного сравнительного вывода о нём нет. Улучшение поиска само по себе не
гарантирует правильность сгенерированного ответа; ответы нужно сверять с источниками.

## Проверка после переключения

Снимок файлов, подготовленный для коммита: **250 passed, 25 skipped**;
рабочая копия с отдельными незакоммиченными изменениями: 263 passed, 25 skipped.
Пропуски относятся к
тестам без отдельной тестовой PostgreSQL. Миграционные тесты проверяют
неизменность исходного индекса, перенос payload и обнаружение неполных векторов
и изменений поколений. Проверка архитектуры Sentrux: новых нарушений и циклов нет.

Живой поиск на новом индексе нашёл контрольный фрагмент в **17/18** вопросов
без указания файла или источника. Пропуск — числовые режимы заявок (`flag_order`).
Правильный документ может быть найден последующим отбором каталога, но этот
прогон проверяет именно прямую выдачу поиска, без генерации и такого отбора.

Повторное скачивание GGUF с нуля прошло проверку размера и SHA256.
`/ready` возвращает 200, все пять сервисов — `ok`; основной чат на порту 3000
отдаёт HTTP 200. Изолированная имитация неверного контекста диалоговой модели
правильно возвращает `context_not_applied`.

Дополнительно проверены два реальных вектора через `POST /v1/embeddings`:
оба конечны и имеют 1024 измерения. Три оригинала скачаны без ошибок.
Запрос `/ready` без ключа возвращает 401. Изолированная подстановка недоступного
embedding-адреса дала `connection_failed` только для `embeddings`, остальные
сервисы оставались успешными. Состояния версий сохранились: 32 indexed,
одна superseded, одна removed. Во время генерации общий ограничитель операций
возвращал ожидаемый 429 для embedding API; после окончания диалога запрос прошёл.

### Ручная оценка ответов без подсказок источника

Вопросы передавались без названия документа и указания места поиска.
Автоматические проверки дали 3/4 для отдельных вопросов и 4/4 для диалога.
Ручная сверка с найденными текстами дала **6/8 приемлемых ответов**:

| Режим и тема | Оценка | Результат |
| --- | --- | --- |
| Отдельно: «Что такое исло?» | Приемлемо | Точное название «Информационная система „Лекарственное обеспечение“» со ссылкой |
| Отдельно: добавление сотрудника из ЕЦП | Ошибка | Нужная инструкция найдена и процитирована, но модель одновременно утверждает, что инструкции нет |
| Отдельно: палаты одного отделения | Приемлемо | ОГРН, `lpu_section_id_ecp`, снятие общей отметки и нужная кнопка |
| Отдельно: SLA и RAM сервера | Приемлемо | Модель признаёт отсутствие данных; автоматическая проверка не распознала формулировку «данных … нет» |
| Диалог, шаг 1: документы выдачи и списания | Приемлемо | Соответствующие группы документов приведены исходным фрагментом; ответ избыточен |
| Диалог, шаг 2: сотрудник из ЕЦП | Ошибка | Повторяется противоречие об отсутствии инструкции при перечисленных действиях |
| Диалог, шаг 3: встроенные отчёты и SSRS | Приемлемо | Логика и контроллеры соответствуют таблице источника: FormController / DefaultController |
| Диалог, шаг 4: палаты отделения | Приемлемо | Возвращён ответ по новой теме с правильным источником |

У четырёх реплик разные ответы и соответствующие текущей теме источники;
тестовый диалог удалён, последующее чтение вернуло 404.
Отдельные генеративные ответы заняли 91,53–151,45 с; точное определение ИС ЛО
выдано извлечением за 0,16 с. Миграция улучшила поиск на контрольном наборе,
но не устранила противоречивые отказы генератора и его высокую задержку.
Эти ограничения требуют отдельного исправления; автоматические проверки
ссылок и ключевых слов их полностью не обнаруживают.
