# Локальный OCR-сервис

Сервис `ocr` в Compose распознаёт текст на русском и английском через
[Tesseract](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html).
Он работает на CPU, не использует LM Studio и не получает ключи, базу данных
или том с оригиналами. API передаёт байты обрабатываемого файла по внутренней
Docker-сети. Порты OCR на компьютере не публикуются.

## Подключение

```powershell
docker compose up -d --build ocr api
```

В Compose `OCR_URL` по умолчанию равен `http://ocr:8000`. Пустое значение
отключает вызовы OCR из API; зависимость запуска от здорового сервиса остаётся.
При запуске API вне Compose задайте адрес доступного OCR-сервиса самостоятельно.
Не публикуйте внутренний OCR API в общедоступную сеть: авторизация загрузок
и ограничения источников выполняются в основном AgentAI API.

Загрузка и переиндексация используют прежние операции и роль `indexer`.
Добавлены PNG, JPEG, TIFF и WebP; их можно выбрать в консоли API либо передать
скрипту `scripts/documents.py`. Для имеющихся сканов PDF достаточно повторной
индексации соответствующей версии. Автоматического обхода или изменения
всех существующих документов при обновлении нет.

## Обработка

- Для PDF сначала работает обычное извлечение текста и таблиц. Только страницы
  с пустым извлечённым текстом передаются на OCR. В смешанном PDF обычные
  страницы сохраняются; текст OCR привязан к исходному номеру страницы.
- Отдельные изображения распознаются целиком; у TIFF сохраняются номера кадров.
- Фрагменты получают `extraction_method=ocr`. Признак хранится в индексе и
  передаётся модели вместе с источником. Оригинал и его контрольная сумма
  не заменяются распознанной копией.
- Ошибка, тайм-аут или неполный ответ OCR останавливает подготовку новой
  генерации до записи векторов и переключения активного индекса.
  Сохранённый оригинал остаётся доступен для повторной индексации.

## Ограничения

Один запрос одновременно; при занятости — 429 без скрытой очереди. Файл —
до 20 МБ, обрабатываемые страницы/кадры — до 50 за запрос, растр страницы —
до 20 мегапикселей. PDF растеризуется при 200 DPI. Тайм-аут Tesseract на
страницу — 30 секунд, всего задания — 180 секунд; клиент ждёт до 210 секунд.
Процесс обработки и его дочерние процессы завершаются при общем тайм-ауте.
Временные файлы удаляются после запроса.

В Compose заданы 2 CPU, 1 ГБ памяти, 64 процесса и временная файловая система
256 МБ. Сервис работает обычным пользователем, с файловой системой только для
чтения; Python-зависимости закреплены в отдельном requirements.lock.

OCR может ошибаться в цифрах, идентификаторах и порядке столбцов. Сервис
возвращает текст, а не доказанную структуру таблицы. Рукописный текст и
автоматическое исправление ориентации сканов PDF не гарантируются.
Изображения внутри DOCX отдельно не распознаются. Страница PDF с непустым
текстовым слоем, например только колонтитулом, автоматически не передаётся
на OCR; для таких документов потребуется отдельный режим обработки.

## Проверка

На этапе подключения OCR полный серверный набор: **193 passed**.
Тогда же проверены синтаксис 113 Python-файлов и зависимости 68 модулей.
Последний общий результат — **229 passed**, см.
[актуальный отчёт](natural-retrieval-fix.md).

Добавлены проверки клиента, смешанных PDF, сохранения таблиц и страниц,
признака OCR в контексте модели, неполных ответов, размеров тела запроса,
выбора страниц, занятости и освобождения сервиса после ошибки.

Реальный сервис проверен на синтетических PNG, скане PDF и смешанном PDF
с русским текстом, английским текстом и числом 12345. Все три сценария
прошли; неверное изображение даёт 422, после чего сервис остаётся здоровым.
Артефакты находятся в игнорируемой папке `work/ocr-smoke/`.
