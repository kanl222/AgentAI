# Настройки локальной модели

22 октября 2026 года параметры генерации вынесены в `.env`, `ModelSettings`
и `.env.example`. Настройки передаются через адаптер LM Studio, включая
инструментальные вызовы и семантический отбор документов.

## Применённый профиль

```dotenv
CHAT_TEMPERATURE=0.7
CHAT_TOP_P=0.8
CHAT_TOP_K=20
CHAT_MIN_P=0
CHAT_PRESENCE_PENALTY=0
CHAT_MAX_TOKENS=4096
CHAT_CONTEXT_LENGTH=16384
```

Первые четыре значения взяты из
[официальных рекомендаций Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507#best-practices).
Штраф оставлен нулевым: повышение в рекомендуемом авторами диапазоне 0–2
нужно оценивать отдельно на повторениях, смешении языков и качестве ответа.
По просьбе пользователя общий контекст уменьшен до 16 384 токенов. Лимит ответа
снижен до 4096, чтобы оставить место для входных данных. Прежний профиль
32768 / 16384 в отчётах ниже относится к предыдущим измерениям.

| Переменная | Допустимые границы | Назначение |
| --- | --- | --- |
| `CHAT_TEMPERATURE` | 0–2 | Температура выборки |
| `CHAT_TOP_P` | 0–1 | Накопленная вероятность кандидатов |
| `CHAT_TOP_K` | 0–1000 | Ограничение количества кандидатов |
| `CHAT_MIN_P` | 0–1 | Минимальная относительная вероятность кандидата |
| `CHAT_PRESENCE_PENALTY` | −2–2 | Штраф за уже встречавшиеся токены |
| `CHAT_MAX_TOKENS` | 256–32768 | Максимальная длина отдельного ответа модели |
| `CHAT_CONTEXT_LENGTH` | От 512, в пределах возможностей модели и памяти | Общий контекст: вход и ответ; должен быть больше `CHAT_MAX_TOKENS` |

Значения за границами ограничиваются ими. Некорректные числа, NaN и бесконечность
в дробных параметрах приводят к ошибке конфигурации. Названия `CHAT_TOP_K`
и `RAG_TOP_K` относятся к разным задачам: первое управляет выборкой токенов,
второе — количеством результатов исходного поиска.

Стандартные параметры передаются через `ChatOpenAI`, `top_k` и `min_p` —
через `extra_body` как параметры совместимого сервера. HTTP-проверки подтверждают,
что в итоговом теле запроса они находятся на верхнем уровне, а не внутри
вложенного объекта `extra_body`.
[Документация адаптера](https://reference.langchain.com/python/langchain-openai/chat_models/base/ChatOpenAI),
[API LM Studio](https://lmstudio.ai/docs/developer/openai-compat/chat-completions).

## Контекст и применение изменений

Контекст задаётся через `CHAT_CONTEXT_LENGTH` в `.env` AgentAI и применяется
при загрузке модели в LM Studio. Для установленной Qwen Q4_K_M проверена оценка памяти и выполнена загрузка
с контекстом 16384 и одним параллельным запросом. До миграции Nomic использовалась с контекстом
2048 на CPU. Теперь embeddings выполняет отдельный Qwen CPU-сервис;
индекс перенесён в новую коллекцию — см. [миграцию](qwen-embedding-migration-20261022.md).

После изменения `CHAT_CONTEXT_LENGTH` на компьютере, где работает LM Studio,
из папки проекта выполните:

```powershell
python scripts/configure_model_context.py
```

Команда читает только `CHAT_MODEL`, `CHAT_CONTEXT_LENGTH`, `CHAT_MAX_TOKENS`
из `.env`; переменные окружения процесса имеют приоритет. Она использует
локальный CLI `lms`, загружает модель с заданным контекстом и `parallel=1`,
затем проверяет фактическое значение. При уже совпадающем контексте загрузки нет.
Для другого файла настроек есть `--env-file`, для пути к CLI — `--lms`.

Если модель уже загружена с другим контекстом, завершите запросы и задания,
затем выполните `python scripts/configure_model_context.py --reload`. Занятый экземпляр
команда не выгружает. Если новая загрузка завершилась ошибкой, проверьте память
и состояние модели в LM Studio; прежний экземпляр после выгрузки не восстанавливается автоматически.

Обновите среду API после изменения `.env`:

```powershell
docker compose up -d --no-deps api
```

`/diagnostics/services` показывает `services.lmstudio.context`: заданный
`configured`, список фактических значений `loaded` и статус `matched`,
`mismatch` или `not_loaded`. При несовпадении или выгруженной модели проверка
возвращает HTTP 503 с кодом `context_not_applied`. Проверка сама модель не загружает.
После автоматической выгрузки LM Studio или ручной загрузки с другими параметрами
повторите команду применения. Перезапуск API сам по себе контекст LM Studio не меняет.
Если переменная отсутствует или пуста, проект не задаёт требование к контексту
и дополнительная проверка контекста отключена; параметры загрузки остаются в LM Studio.

Установленная версия LM Studio должна поддерживать `GET /api/v1/models`,
а `LMSTUDIO_BASE_URL` для этой проверки должен оканчиваться на `/v1`.
[Список моделей и параметры загруженных экземпляров](https://lmstudio.ai/docs/developer/rest/list),
[настройка контекста и оценка памяти через CLI](https://lmstudio.ai/docs/cli/local-models/load).

Лимит 16384 — максимум, а не требование выдавать длинный ответ. Вход и выход
вместе должны помещаться в контекст. Для других моделей профиль следует
подбирать отдельно.

После изменения исходников требуется сборка API. Первое обновление профиля генерации было собрано
из предыдущего рабочего образа с заменой только файлов настройки и адаптера,
чтобы не включать другие локальные изменения. Предыдущий `.env` сохранён
в закрытой резервной копии; путь записан в локальном
`work/model-settings-backup-path.txt`. Образ для отката указан в
`work/model-settings-before-image.txt`. Эти локальные файлы не входят в Git.

## Начальный профиль для 6 ГБ VRAM и 16 ГБ ОЗУ

Для Qwen3-4B-Instruct-2507 Q4_K_M начните с:

```dotenv
CHAT_CONTEXT_LENGTH=16384
CHAT_MAX_TOKENS=4096
CHAT_TEMPERATURE=0.7
CHAT_TOP_P=0.8
CHAT_TOP_K=20
CHAT_MIN_P=0
CHAT_PRESENCE_PENALTY=0
```

Один параллельный запрос; Qwen embeddings работает на CPU в отдельном
сервисе Compose. Остальные сервисы Docker также используют оперативную память.
Это исходная рекомендация для проверки на таком оборудовании, а не измеренный оптимум.

22 октября 2026 года `lms load --estimate-only` для установленной Qwen Q4_K_M
и `parallel=1` показал:

| Контекст | Оценка памяти GPU |
| --- | --- |
| 8192 | 2,97 ГиБ |
| 16384 | 3,54 ГиБ |
| 32768 | 4,67 ГиБ |

Оценка не включает всю нагрузку рабочего стола и сервисов; фактическое потребление
нужно измерять при запросах. На видеокарте с 6 ГБ этот профиль пока не испытывался.
При нехватке памяти попробуйте контекст 8192 и максимум ответа 2048, затем повторите
проверку обычных вопросов по документам. Сокращение лимита ответа ограничивает длину
генерации; размер выделенного KV-кэша определяется прежде всего контекстом и параметрами загрузки.

## Отдельная модель embeddings

С 22 октября поиск использует Qwen3-Embedding-0.6B Q8_0 в CPU-сервисе Compose.
`EMBED_BASE_URL=http://embeddings:8080/v1`, `EMBED_MODEL=qwen3-embedding-0.6b`,
`QDRANT_COLLECTION=agentai_qwen3_embedding_0_6b`. Ключ задаётся отдельно через
`EMBED_API_KEY`. `EMBED_QUERY_INSTRUCTION`:
`Given a web search query, retrieve relevant passages that answer the query`.
Внутренний адаптер добавляет инструкцию только к поисковым вопросам.

Сервис ограничен четырьмя CPU и 2 ГБ RAM, GPU отключён параметрами запуска.
Контекст embeddings — 4096, размерность — 1024. `CHAT_CONTEXT_LENGTH` и
`CHAT_MAX_TOKENS` относятся к диалоговой модели и не меняют эти параметры.
Первичная загрузка: `python scripts/download_embedding_model.py`.
Порядок обновления существующей установки: [миграция индекса](qwen-embedding-migration-20261022.md).
