# Настройка и оптимизация AgentAI

> Исторический отчёт: оптимизация и измерения на момент этого этапа.
> Числа тестов, задержки и состояние сервиса ниже относятся к этому этапу.
> Текущее поведение и последние проверки: [исправление поиска](natural-retrieval-fix.md),
> [навигатор документации](README.md).

21 октября 2026 года. Изменения применены к рабочему API.

## Что изменено

- Клиент Qdrant закреплён на **1.16.2**, как и работающий сервер. Прежний клиент
  1.19.1 выдавал предупреждение о несовместимости. Сам сервер и его хранилище
  не обновлялись. Выбор одной minor-ветки соответствует
  [правилам совместимости Qdrant](https://qdrant.tech/documentation/upgrades/).
- Корпус, указатели поколений и актуальные метаданные читаются с одним
  подключением PostgreSQL вместо двух. Актуальность и права проверяются при
  каждом поиске, включая попадания в кеш.
- Добавлен ограниченный кеш векторов запросов. Повтор одинакового вопроса
  использует прежний вектор, но выполняет поиск по текущему разрешённому корпусу.
  Смена экземпляра embeddings сбрасывает векторы. Ошибки не кешируются.
- Список заданий читается одним запросом вместо получения каждого задания
  отдельно. Проверки владельца, источников и скрытия результатов сохранены.
- Простаивающий worker проверяет очередь через уже открытое соединение лидера.
  При пустой очереди он не открывает отдельные подключения для GPU-блокировки
  и попытки забрать задание.
- В Compose настроены параметры кешей, healthcheck API и 30 секунд на остановку.
  Рабочий API пересоздан из проверенного образа; теперь используется и новая
  модульная архитектура из предыдущего этапа.

Qdrant перед настройкой: версия 1.16.2, статус `green`, оптимизатор `ok`,
123 вектора, два сегмента, около 59 МиБ RAM. Векторная часть прогретого поиска
занимала единицы миллисекунд. Параметры HNSW и структура коллекции сохранены:
замер указывал на расходы приложения. Поиск причин выполнялся по
[официальному навыку диагностики Qdrant](https://skills.qdrant.tech/search?query=filtered+search+latency+payload+indexes+docker).

## Настройки

| Переменная | Значение | Назначение |
| --- | ---: | --- |
| `RETRIEVAL_CACHE_ENTRIES` | 4 | Максимум снимков корпуса и лексических индексов |
| `RETRIEVAL_CACHE_TTL_SECONDS` | 30 | Время повторного использования снимка корпуса |
| `QUERY_EMBED_CACHE_ENTRIES` | 64 | Максимум векторов вопросов |
| `QUERY_EMBED_CACHE_TTL_SECONDS` | 300 | Время повторного использования вектора вопроса |

Настройки добавлены в `.env.example` и Compose. Рабочий `.env` не изменялся:
Compose применяет указанные значения по умолчанию, сохраняя возможность задать
свои. Нулевой размер кеша отключает его. Нулевой TTL отключает повторное
использование соответствующих снимков/векторов. Настройки считываются при
создании хранилища; после изменения требуется пересоздать API.

Кеши находятся только в памяти процесса. Кеш векторов не хранит готовые ответы
и не заменяет проверку доступа. Изменение поколения индекса продолжает
инвалидировать снимок корпуса; метаданные актуальности не кешируются.

## Замеры

Сравнивались одинаковые два вопроса на рабочем индексе: восемь последовательных
поисков, из которых первые два исключены из медианы. Замер охватывает вызов
`Store.search`, включая Qdrant, PostgreSQL и при необходимости embeddings.

| Состояние | Медиана прогретого поиска |
| --- | ---: |
| Рабочая версия до обновления | 108,03 мс |
| Собранный кандидат до обновления | 28,16 мс |
| Применённая версия | 21,84 мс |

Для этого повторяемого сценария задержка снизилась примерно на **80%**.
Идентификаторы, тексты и порядок найденных фрагментов совпали во всех восьми
замерах. На 30 отдельных синтетических вопросах с реальной Nomic embeddings
порядок результатов также совпал; Recall@3 и MRR@6 остались равны 1,0.

Это замер поиска для небольшого корпуса и повторных вопросов. Он не означает
такого же ускорения генерации, холодного запроса или поиска на больших корпусах.
Первый вызов может включать загрузку модели LM Studio.

## Проверки

- **126 серверных тестов прошли** с отдельной PostgreSQL и клиентом Qdrant 1.16.2.
- Проверены TTL, предел размера, отключение кеша, смена модели, ошибки embeddings,
  защита кеша от изменения вызывающим кодом и сохранение ограничений доступа.
- Проверка списка заданий подтверждает одно подключение и скрытие закрытого
  источника и результата после отзыва доступа.
- Три последовательных живых запроса через очередь завершились успешно примерно
  за 2,05–2,06 секунды: использован источник, проверка ответа пройдена, один ход
  истории сохранён. Проверочные диалоги затем удалены.
- Проверены `/ready`, обязательность авторизации и прокси пользовательского чата.
  Контейнеры API и чата имеют статус `healthy`.

Первый живой запрос, запущенный одновременно с прямым диагностическим обращением
к модели, завершился `OpenAIInvalidRequestError`. Короткий запрос, вызов инструмента
и последующие раздельные полные запросы прошли. Точная причина единичного отказа
не установлена; модели и их параметры наугад не менялись. Диагностический профиль
теперь использует общую GPU-блокировку, чтобы не конкурировать с рабочей очередью.

Локальные отчёты исключены из Git: `work/tuning-tests.xml`,
`work/tuning-baseline.json`, `work/tuning-candidate.json`,
`work/tuning-applied.json`, `work/tuning-real-search.json`,
`work/tuning-live-check.json`, `work/tuning-data-check.json`.

## Сохранность данных и возврат версии

Перед обновлением API остановлен при пустой очереди. Создана согласованная копия:

- PostgreSQL в формате `pg_dump -Fc`;
- архив файлов тома `/app/data`;
- snapshot коллекции Qdrant и сведения об aliases.

Копия находится в `backups/tuning-20261021-b8871a84`. PostgreSQL восстановлена
в отдельную тестовую БД, snapshot — в отдельный Qdrant 1.16.2. Проверены 123 вектора
и SHA256 всех 34 оригиналов. Создание и восстановление snapshot выполнены через
[API версии 1.16](https://api.qdrant.tech/v-1-16-x/api-reference/snapshots/create-snapshot).

После применения миграций и завершения проверок хеши исходных таблиц совпали:
34 версии документов, 43 диалога, 45 ходов истории, 12 заданий и 26 указателей
индекса. Эти числа относятся к моменту проверки, а не к постоянным ограничениям.
Добавлена только таблица учёта миграций схемы.

`manifest.json` в каталоге копии содержит контрольные суммы и тег прежнего образа
для возврата версии. Временные контейнеры проверки восстановления удалены.
Запущенные PostgreSQL, Qdrant и пользовательский чат не пересоздавались.
