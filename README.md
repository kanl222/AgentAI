# AgentAI — локальный ИИ-агент организации

MVP для поиска по документам и исходному коду, ответов со ссылками на источники
и подготовки предложений по доработке проектов. Диалоговая модель работает
в LM Studio, эмбеддинги Qwen — в отдельном CPU-сервисе Docker,
интерфейс общения — отдельный AgentAI Chat, права доступа проверяет сервер AgentAI.

Два отдельных сайта находятся в [web](web/README.md): пользовательский чат
на Node.js 24 (`web/chat`, порт 3000) и консоль тестирования API `web/api-console` на порту 8000.
Исходный Open WebUI в `frontend` сохранён как необязательный старый интерфейс
([инструкция](docs/frontend-webui.md), профиль Compose `legacy-webui`, порт 3001).

Документация сверена с исходниками и последним проверенным обновлением
22 октября 2026 года. [Навигатор документации](docs/README.md) отделяет текущие
инструкции от отчётов отдельных этапов. Последнее исправление поиска без
подсказок источника и смены темы описано в
[актуальном отчёте](docs/natural-retrieval-fix.md).

Быстрые переходы: [запуск](#запуск-в-windows-и-wsl2) ·
[загрузка документов](#загрузка-документов-в-базу-знаний) ·
[диалоги и очередь](#диалоги-библиотека-и-очередь) ·
[проверки](#тесты-и-критерии-приёмки) ·
[диагностика](#если-что-то-не-работает).

## Возможности

- Загрузка PDF, DOCX, TXT, Markdown и изображений с сохранением оригиналов и версий.
- Локальный OCR на русском и английском для сканов PDF и изображений.
- Сохраняемые диалоги, очередь заданий, библиотека и актуальность документов.
- Дополнительный выбор документов по смыслу вопроса без подсказки имени файла.
- Проверка ссылок и отдельных противоречий; возврат цитаты при повторной ошибке.
- Гибридный поиск: векторный Qdrant и лексический BM25, объединённые RRF (`k=60`).
- Индексация исходников GitLab на зафиксированном коммите.
- Ссылки на страницы PDF, абзацы и строки таблиц DOCX, пути и строки кода.
- Ограничение поиска доступными пользователю источниками.
- Выбор инструментов моделью, навыки `SKILL.md`, ограничение числа шагов.
- Дополнительный инструмент чтения метаданных SQL Server.

Агент предлагает изменения кода в чате. MCP, применение патчей и запуск тестов
самим агентом пока не реализованы.

## Схема работы

```text
Пользователь → AgentAI Chat (Node.js 24, :3000)
                          ↓ /api/*
                   AgentAI (FastAPI + LangGraph, :8000)
                          ├─ LM Studio: диалоговая модель
                          ├─ embeddings: Qwen3-Embedding-0.6B на CPU
                          ├─ PostgreSQL: версии, история, очередь и поколения
                          ├─ Qdrant: текст, векторы и ссылки
                          ├─ Файловый архив оригиналов
                          ├─ OCR: распознавание сканов на CPU
                          ├─ GitLab: чтение исходников, если настроен
                          └─ SQL Server: метаданные, если настроен

Консоль API (:8000) → тот же AgentAI
```

LangChain связывает модель с инструментами, LangGraph управляет шагами.
Облачный API OpenAI для генерации не настроен: используется совместимый API
LM Studio. Синхронизация GitLab обращается к настроенному серверу GitLab.

## Требования

- Windows 11, WSL2 и Docker Desktop с Linux-контейнерами.
- LM Studio и актуальный драйвер видеокарты.
- Целевая конфигурация: 6 ГБ видеопамяти и 16 ГБ оперативной памяти.
- Python 3.11+ для административных скриптов и отдельного запуска backend.
- Node.js 24 для запуска чата вне Docker; в контейнере он уже установлен.

LM Studio работает отдельно от Docker; передача GPU контейнерам не нужна.
Для диалога используется Qwen3 4B Q4_K_M, для поиска — Qwen3-Embedding-0.6B
Q8_0: 1024 измерения, контекст 4096, только CPU. Compose выделяет сервису
четыре CPU и до 2 ГБ RAM; модель занимает около 610 МиБ на диске.
Диалоговая модель использует GPU. Шаблон задаёт её контекст 32768; для 6 ГБ VRAM
профиль с меньшим контекстом описан в [настройках модели](docs/model-configuration.md). Расход памяти
и скорость нужно измерить на вашем компьютере: это целевая конфигурация,
а не гарантия производительности. Операции API выполняются последовательно.

## Запуск в Windows и WSL2

### 1. Подготовить настройки

Откройте PowerShell в папке проекта:

```powershell
cd D:\Source\AgentAI
Copy-Item .env.example .env
```

Копируйте шаблон только при первой настройке: существующий `.env` содержит
рабочие ключи. В WSL путь проекта: `/mnt/d/Source/AgentAI`.

Создайте независимые случайные ключи для чтения и загрузки, а также пароль
PostgreSQL. Эта команда выводит одно значение; повторите её для каждого секрета:

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

Сохраните значения в защищённом месте. Создайте записи пользователей, вводя
соответствующие ключи в скрытом приглашении:

```powershell
python scripts/make_user.py reader --sources docs-demo,repo-demo
python scripts/make_user.py indexer --roles reader,indexer --sources docs-demo,repo-demo
```

Соберите выведенные записи в JSON-массив и запишите одной строкой в `.env`:

```dotenv
AGENT_USERS='[{"name":"reader","sha256":"<хеш ключа чтения>","roles":["reader"],"sources":["docs-demo","repo-demo"]},{"name":"indexer","sha256":"<хеш ключа загрузки>","roles":["reader","indexer"],"sources":["docs-demo","repo-demo"]}]'
```

Замените `<...>` реальными SHA256 из скрипта. Пользователей по умолчанию нет;
`AGENT_USERS=[]` не предоставляет доступ. В `POSTGRES_PASSWORD` запишите отдельный
случайный hex-пароль: Compose использует его в адресе подключения. При первом
запуске он создаёт учётную запись БД; изменение `.env` не меняет пароль уже
существующей БД автоматически.

В `WEBUI_READER_KEY` укажите исходный ключ чтения, а не хеш: его также используют
административные скрипты загрузки и оценки. `DOCUMENTS_INDEXER_KEY` настраивается
отдельно ниже. `WEBUI_SECRET_KEY` нужен только при включении старого Open WebUI;
для него создайте ещё один случайный секрет. Основной чат использует личный ключ,
который пользователь вводит в браузере.

### 2. Настроить LM Studio

1. Установите и загрузите диалоговую модель. Qwen embeddings запускается отдельно в Compose.
2. Запустите сервер на порту `1234` в разделе разработчика LM Studio.
3. Разрешите доступ из Docker, ограничив сетевой доступ доверенными узлами.
4. Если включена авторизация, укажите токен в `LMSTUDIO_API_KEY`.
5. Сверьте идентификатор диалоговой модели с ответом `/v1/models`.

Для сервера на том же компьютере:

```powershell
curl.exe http://localhost:1234/v1/models
```

При включённой авторизации нужен заголовок `Authorization: Bearer ...`.
Наличие модели в списке не подтверждает её загрузку и готовность к генерации.
Проверьте загрузку и поддержку вызовов инструментов в LM Studio.

| Параметр `.env` | Назначение |
| --- | --- |
| `LMSTUDIO_BASE_URL` | Адрес API LM Studio с окончанием `/v1` |
| `LMSTUDIO_API_KEY` | Токен LM Studio; без авторизации — условное значение `lm-studio` |
| `CHAT_MODEL` | Точный идентификатор диалоговой модели |
| `EMBED_MODEL` | CPU-модель: `qwen3-embedding-0.6b` |
| `EMBED_BASE_URL` | В Compose — `http://embeddings:8080/v1`; вне Docker нужен доступный адрес сервиса |
| `EMBED_API_KEY` | Отдельный ключ embedding API; локальный сервис использует условное значение |
| `EMBED_QUERY_INSTRUCTION` | Инструкция Qwen для поискового запроса; документы передаются без префикса |
| `QDRANT_COLLECTION` | `agentai_qwen3_embedding_0_6b`; смена модели требует переноса всего индекса |
| `CHAT_TEMPERATURE` | Температура генерации: 0,7; диапазон 0–2 |
| `CHAT_TOP_P` | Вероятностный порог TopP: 0,8; диапазон 0–1 |
| `CHAT_TOP_K` | Число кандидатов TopK: 20; диапазон 0–1000 |
| `CHAT_MIN_P` | Порог MinP: 0, отключён; диапазон 0–1 |
| `CHAT_PRESENCE_PENALTY` | Штраф за присутствовавшие токены: 0; диапазон −2–2 |
| `CHAT_MAX_TOKENS` | Максимум токенов ответа: 16 384; диапазон 256–32 768 |
| `CHAT_CONTEXT_LENGTH` | Контекст входа и ответа; в шаблоне 32 768. Применяется командой `python scripts/configure_model_context.py` на компьютере с LM Studio |
| `MAX_STEPS` | Лимит шагов генерации основного графа: 4, диапазон 1–8; отбор документов выполняется отдельно |
| `QDRANT_URL` | В Compose — `http://qdrant:6333` |
| `AGENT_USERS` | JSON-массив пользователей, хешей ключей, ролей и источников |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL; Compose формирует `DATABASE_URL` |
| `WEBUI_READER_KEY` | Ключ `reader` для административных скриптов и старого WebUI |
| `WEBUI_SECRET_KEY` | Секрет старого Open WebUI, если он включён |
| `DOCUMENTS_INDEXER_KEY` | Отдельный ключ загрузчика; настраивается скриптом |
| `OCR_URL` | В Compose — `http://ocr:8000`; пустое значение отключает вызовы OCR |
| `CONVERSATION_RETENTION_DAYS` | Срок хранения диалогов: 30 дней |
| `MAX_PENDING_JOBS` | Лимит ожидающих заданий: 32 |
| `CHAT_QUEUE_WAIT_SECONDS` | Ожидание совместимого chat API: 240 секунд |
| `GITLAB_URL`, `GITLAB_TOKEN`, `GITLAB_SOURCES` | Дополнительные настройки GitLab |
| `SQL_CONNECTION_STRING` | Подключение SQL Server; пустое значение отключает его |

Для LM Studio на Windows-хосте адрес из Docker Desktop:
`http://host.docker.internal:1234/v1`. Для удалённого сервера укажите его
доступный сетевой адрес. Для AgentAI вне Docker на том же компьютере:
`http://localhost:1234/v1`.

Параметры генерации задаются в `.env` и передаются в каждом запросе к LM Studio,
включая отбор документов. Значения шаблона соответствуют рекомендациям
Qwen3-4B-Instruct-2507. После изменения пересоздайте API; одна правка параметров
в интерфейсе LM Studio не меняет значения, которые явно передаёт AgentAI.
Длину контекста LM Studio настраивает отдельно: для ответа до 16 384 токенов
нужно оставить место также для документов, истории и вопроса. Применённый
контекст Qwen — 32 768. Порядок загрузки, проверки и ограничения описаны в
[конфигурации модели](docs/model-configuration.md).

### 3. Запустить контейнеры

```powershell
python scripts/download_embedding_model.py
docker compose up -d --build postgres qdrant ocr embeddings api chat
docker compose ps
```

Скрипт скачивает закреплённую версию GGUF и проверяет SHA256.
При обновлении существующей установки выполните [миграцию индекса](docs/qwen-embedding-migration-20261022.md):
простая замена модели несовместима с прежними 768-мерными векторами Nomic.

- Чат: <http://localhost:3000>.
- Консоль API: <http://localhost:8000>.
- Документация API: <http://localhost:8000/docs>.
- Проверка работы процесса: <http://localhost:8000/health>.

В чате нажмите «Подключение» и введите личный ключ API. Ключ хранится только
в памяти вкладки. Для тестирования запросов и управления документами откройте
отдельную консоль API. Если порт 3000 занят прежним Open WebUI, остановите его
командой `docker compose stop webui` перед запуском `chat`; данные сохранятся.

Для первого вопроса загрузите документ через консоль пользователем с ролями
`reader,indexer`. После успешной индексации задайте в чате обычный вопрос по его
содержанию — указывать имя файла не обязательно. Проверьте приведённый источник.
Команды для файлов и папок описаны ниже.

`/health` подтверждает работу процесса. Для проверки PostgreSQL, Qdrant, LM Studio,
CPU-сервиса embeddings и настроенного OCR используйте `/ready` или `/diagnostics/services` с личным
ключом читателя. В консоли API есть кнопка «Проверить сервисы». Ответ содержит
отдельные статусы, причины ошибок и подсказки; при сбое возвращается HTTP 503.
Успешная проверка не заменяет реальный вопрос: генерация, вычисление эмбеддингов
и распознавание не запускаются. [Описание диагностики](docs/service-diagnostics.md).

### Необязательный старый Open WebUI

```powershell
docker compose --profile legacy-webui up -d --build webui
```

Адрес старого интерфейса: <http://localhost:3001>. Подробная
[инструкция](docs/frontend-webui.md).

Следующие настройки относятся только к старому Open WebUI, если включён профиль
`legacy-webui`. При первом запуске создайте администратора WebUI. Затем отключите регистрацию
в настройках WebUI и установите `ENABLE_SIGNUP: "false"` в `compose.yaml`.
Сохранённые настройки могут иметь приоритет над окружением: проверьте фактическое
состояние регистрации после пересоздания WebUI.

В административных настройках подключения WebUI укажите:

```text
Адрес: http://api:8000/v1
Ключ: значение WEBUI_READER_KEY
Модель: local-agent
Потоковая выдача: выключена
Ollama: выключена
```

Модель может отображаться под названием «Агент организации», заданным
администратором. Подключайте WebUI через AgentAI: прямое соединение с LM Studio
обходит инструменты и проверки прав AgentAI. Чат, API и старый WebUI опубликованы
только на `127.0.0.1`; PostgreSQL, Qdrant и OCR не публикуют порты на хосте. `.env` загружается Compose;
отдельный запуск `uvicorn` сам его не читает.

## Загрузка документов в базу знаний

### Подготовить ключ загрузки

Администратор выполняет:

```powershell
python scripts/setup_documents.py --source docs-demo
docker compose up -d --build api
```

Читатель из `WEBUI_READER_KEY` уже должен иметь доступ к `docs-demo` в `AGENT_USERS`.
Скрипт добавляет отдельный ключ загрузки в `.env`; повторный запуск сохраняет
его значение. Рабочие ключи скрипт не печатает.

### Загрузить файл и скачать оригинал

```powershell
python scripts/documents.py --env .env upload "D:\Documents\Regulation.pdf" --source docs-demo
python scripts/documents.py --env .env list
python scripts/documents.py --env .env list --offset 50
python scripts/documents.py --env .env download VERSION_UUID --output "D:\Documents\restored.pdf"
```

Замените путь существующим файлом, а `VERSION_UUID` — идентификатором версии.
Поддерживаются PDF, DOCX, TXT, MD, PNG, JPEG, TIFF и WebP; ограничение — 20 МБ на файл.
Страницы PDF без текстового слоя и отдельные изображения распознаёт локальный
сервис OCR на русском и английском. Настройка и ограничения: [docs/ocr.md](docs/ocr.md).
Скачивание не перезаписывает существующий файл.

Загрузка возвращает `document_id`, `version` и `download_url`. Повторная загрузка
того же имени в тот же источник создаёт версию. Другое имя создаёт отдельный
документ. Для сохранения идентичности при переименовании передайте
`--document-id` из предыдущей загрузки.

`--env` предназначен для компьютера администратора: не передавайте `.env`
сотрудникам. Без него скрипт скрыто запрашивает личный ключ пользователя.

### Загрузить папку

Сначала проверьте список файлов:

```powershell
python scripts/upload_folder.py "D:\Documents" --source docs-demo --dry-run
python scripts/upload_folder.py "D:\Documents" --source docs-demo --env .env
```

Вложенные папки обрабатываются последовательно. Пропускаются скрытые и служебные
каталоги, символьные ссылки, внешние точки соединения и неподдерживаемые форматы.
`--dry-run` не читает ключи и не выполняет сетевых запросов.

Неизменившиеся файлы пропускаются по идентификатору и SHA256, изменённые создают
версию. Ошибки файлов приводят к ненулевому коду завершения; исправьте причину
и повторите загрузку. Удаление локального файла не удаляет его из базы.

Идентификатор зависит от источника и относительного пути. Сохраняйте корневую
папку и `--namespace` между загрузками. Для независимых папок используйте разные
постоянные пространства имён:

```powershell
python scripts/upload_folder.py "D:\Finance" --source docs-demo --namespace Finance --env .env
python scripts/upload_folder.py "D:\HR" --source docs-demo --namespace HR --env .env
```

`namespace` разделяет идентификаторы, но не права. Для разных правил доступа
нужны разные источники в `AGENT_USERS`. Перемещение, переименование или смена
пространства имён создаёт новую идентичность. Без `--env` загрузка папки требует
личный ключ с ролями `reader` и `indexer`.

После загрузки откройте AgentAI Chat и задайте вопрос о документе. В старом
Open WebUI выберите `local-agent`; его кнопка прикрепления файла использует
собственный механизм и автоматически не заполняет архив AgentAI. Скрипт папки предназначен для документов; исходники
индексируются через GitLab или загружаются как подготовленный документ с кодом.

## Диалоги, библиотека и очередь

Откройте <http://localhost:8000/library>. Страница позволяет вести сохраняемые
диалоги, загружать файлы в очередь, видеть версии и ошибки, менять актуальность,
повторять индексацию и убирать текущий документ из поиска. Ключ вводится в форме
и хранится только в памяти страницы. Для управления нужны роли `reader,indexer`;
общий ключ WebUI предназначен только для чтения. Создать личную запись можно
через `scripts/make_user.py` и добавить её в `AGENT_USERS`. Не передавайте
общий ключ загрузчика всем сотрудникам.

PostgreSQL хранит каталог оригиналов, диалоги, очередь и указатели активных
поколений индекса. Файлы остаются в томе `documents`, векторы — в Qdrant.
Пароль PostgreSQL задаётся в `POSTGRES_PASSWORD` (случайный hex без специальных
символов URL). Compose формирует `DATABASE_URL`; для отдельного запуска API
задайте её явно. Порт PostgreSQL на хосте не опубликован. Том `postgres` тоже
нужно включать в резервную копию.

При переходе со старой версии выполните после запуска PostgreSQL и нового API:

```powershell
docker compose up -d --build postgres api
docker compose exec -T api python scripts/migrate_postgres.py
```

Миграция проверяет SHA256 каждого оригинала и число перенесённых записей в одной
транзакции. Старый `catalog.sqlite3` и файлы не удаляются. Повторный запуск
не затирает новые состояния PostgreSQL. SQLite сохранён только для чтения
старого каталога при миграции и старых автономных тестов. Основная БД — PostgreSQL.

### Память диалога

`POST /conversations` создаёт диалог; `GET /conversations` перечисляет свои,
`GET /conversations/{id}` читает историю, `DELETE /conversations/{id}` удаляет её
вместе с заданиями этого диалога. В `/chat` и `/jobs/chat` передавайте
`conversation_id`; без него создаётся новый диалог. История привязана к
подтверждённому ключом пользователю, ограничена по объёму и повторно проверяется
по правам. После удаления документа из поиска его фрагменты не используются
как контекст следующего ответа.

В PostgreSQL сохраняется не более 40 последних пар сообщений. Контекст модели
ограничен 6000 символами истории, длинный последний ответ сокращается с отметкой.
`CONVERSATION_RETENTION_DAYS` — срок хранения, по умолчанию 30 дней;
очистка выполняется при обращении к диалогам. Это не отдельный фоновый планировщик.

В старом WebUI память использует `X-OpenWebUI-Chat-Id`; Compose включает передачу этого
заголовка. После обновления пересоздайте WebUI. Также API принимает `chat_id`
в теле совместимого запроса. Заголовки имени/ID пользователя не предоставляют
права: личность определяется Bearer-ключом. При общем ключе WebUI пользователи
остаются одним backend-пользователем; для индивидуальной изоляции нужны личные
ключи или отдельная интеграция идентификации. Если клиент не передаёт идентификатор,
каждый запрос создаёт отдельный диалог.

### Очередь и безопасное обновление индекса

Маршруты постановки заданий возвращают 202 и идентификатор задания:

| Маршрут | Действие |
| --- | --- |
| `POST /jobs/documents` | Загрузить оригинал и поставить индексацию в очередь |
| `POST /jobs/gitlab` | Поставить синхронизацию источника GitLab |
| `POST /jobs/chat` | Поставить вопрос в очередь |
| `GET /jobs`, `GET /jobs/{id}` | Свои задания, состояние, прогресс, результат или ошибка |
| `DELETE /jobs/{id}` | Отменить ожидающее задание |
| `POST /documents/{version}/reindex` | Переиндексировать выбранную версию |
| `PATCH /documents/{version}` | Изменить `validity` и `note` |
| `DELETE /documents/{version}` | Поставить удаление текущего документа из поиска |

Для статуса документа: `current`, `obsolete` или `draft`. Неактуальные материалы
остаются доступны с предупреждением; «убрать из поиска» сохраняет оригинал.
Удалить из поиска можно только текущую индексированную версию. Старую версию
можно сделать текущей через явную переиндексацию.

Состояния заданий: `queued`, `running`, `succeeded`, `failed`, `cancelled`.
`MAX_PENDING_JOBS` ограничивает очередь (по умолчанию 32). Один потребитель
использует общую блокировку GPU-операций. Права перепроверяются при исполнении.
После перезапуска API незавершённые задания повторяются; выполнение имеет
семантику «как минимум один раз». Отмена выполняющегося задания пока не поддерживается.
Синхронные /chat и /ingest/* сохранены для совместимости и могут возвращать 429.
Запросы WebUI /v1/chat/completions по умолчанию проходят через очередь и ждут
результат до CHAT_QUEUE_WAIT_SECONDS (по умолчанию 240 секунд). При превышении
ожидания возвращается 504 с job_id; задание продолжает выполняться. Для
явного фонового режима используйте /jobs/chat или библиотеку.

Новая индексация записывается в отдельное поколение Qdrant. После успешной записи
всех фрагментов PostgreSQL транзакционно переключает указатель и состояние
версии. Незавершённые поколения не видны поиску, старый индекс сохраняется при
ошибке. Старые поколения пока остаются в Qdrant: их очистка требует отдельной
процедуры обслуживания. Согласованная резервная копия должна включать PostgreSQL,
Qdrant и оригиналы; потеря указателей PostgreSQL нарушает выбор поколения.

### Дочитывание и проверка качества

Инструмент `read_source` и `GET /sources/{chunk_id}` читают соседние фрагменты
того же документа с проверкой доступа. Первый результат автоматически дополняется
соседним контекстом. JSON контекста сохраняется корректным при ограничении объёма.
Таблицы DOCX извлекаются в порядке документа с заголовками столбцов у строк.
Таблицы PDF с распознаваемыми границами извлекаются построчно с названиями
столбцов у каждого значения. Обычные текстовые страницы сохраняют прежнее
извлечение. Объединённые ячейки помечаются как неопределённые; сканы требуют
OCR, а таблицы без границ пока не восстанавливаются. После обновления обработчика
нужна переиндексация существующих PDF с таблицами через библиотеку или API.

Каждый новый вопрос сначала ищется по всему разрешённому корпусу. Настоящее
уточнение дополняет поиск контекстом истории; документы предыдущей темы не
ограничивают новую тему. Явно указанный файл или идентификатор задаёт область
поиска. Для самостоятельных вопросов без такого ограничения та же локальная
модель дополнительно выбирает документы из краткого каталога, а ответ строится
по их оригинальным фрагментам. Короткие определения могут возвращаться прямо
из структурированного источника, без генерации модели.

Модель ссылается на найденные фрагменты метками `[S1]`, `[S2]`; API заменяет их
проверенными `citation`. Неполученные источники и неподтверждённые веб-ссылки
в тексте ответа помечаются с предупреждением. URL внутри блоков кода сохраняются.
Перед выдачей проверяются некоторые явные противоречия: отсутствие значений
при их перечислении и перепутанные значения в восстановленных строках таблиц.
Если найдено такое противоречие, пропущена ссылка или указан неподтверждённый
адрес, API может один раз запросить исправление в пределах `MAX_STEPS`.
Замечание содержит конкретную ошибку и исходный фрагмент. Второй ответ проверяется
заново; при повторной выявленной ошибке содержания или ссылки API может вернуть
точную цитату проверенного источника. В остальных случаях остаётся предупреждение.
Поле `validation` в `/chat` содержит результат, замечания и сведения о попытке
исправления.
Это проверка происхождения ссылки, а не доказательство истинности утверждения.
Диагностическое поле `retrieval` сообщает статус дополнительного отбора
(`catalog_selection`: `not_needed`, `completed`, `unavailable`) и использование
цитаты вместо повторного пересказа (`extractive_fallback`).

`scripts/benchmark_answers.py` сравнивает уже загруженные модели через тот же
конвейер ответов на одинаковых вопросах корпуса CF. Он не меняет индекс и не
сохраняет диалоги. В отчёт входят проверки фактов, ссылок и параметров SQL,
число уточнений, время ответа, токены и хеш первоначальных доказательств.
Для воспроизводимого сравнения нужны одинаковые контекст, параллелизм и параметры
генерации; память GPU измеряется отдельно, фактический режим рассуждений тоже
нужно проверять по метрикам, а не только по переданному параметру.

Для русского поиска добавлены признаки общих начал слов, а точные идентификаторы
сохранены. `SEARCH_ALIASES` позволяет задать проверенные сокращения, например
`{"СЭД":["система электронного документооборота"]}`. Пример не является
автоматическим словарём вашей организации. `used_sources` содержит ссылки,
явно присутствующие в ответе; `sources` — все найденные материалы. Backend
предупреждает об устаревших источниках и отсутствии точных ссылок, но не доказывает
правильность каждого утверждения и не разрешает противоречия автоматически.

Повторяемая оценка поиска на отдельном синтетическом корпусе, без изменения базы:

```powershell
docker compose exec -T api python scripts/evaluate_rag.py --dataset examples/rag-regression.json --output /tmp/rag-evaluation.json
```

Набор `examples/rag-regression.json` содержит 38 случаев, включая границы
фрагментов, таблицу и недоступные источники. Исходный набор из 30 вопросов
сохранён в `examples/rag-evaluation.json`.
Метрики Recall@3 и MRR@6 оценивают поиск, а не качество генерации. Реальные
эталоны сотрудников и ручная проверка сложных таблиц остаются необходимыми.

Интеграционные тесты PostgreSQL запускаются с `TEST_DATABASE_URL`, указывающей
на тестовую БД. Для каждого теста создаётся отдельная схема, которая затем
удаляется. Рабочую БД лучше не использовать; без переменной новые PostgreSQL-тесты
пропускаются. Обычные автономные тесты остаются доступны.

## Исходники GitLab и анализ кода

Настройте токен с правом `read_api` и доступом только к нужным проектам:

```dotenv
GITLAB_URL=https://gitlab.example.org
GITLAB_TOKEN=<токен проекта>
GITLAB_SOURCES='{"repo-demo":{"project":123,"ref":"main"}}'
```

Замените заполнители реальными настройками. Разрешите `repo-demo` загрузчику
и нужным читателям через `AGENT_USERS`. Выполните `POST /ingest/gitlab` с ключом
роли `indexer`; пример приведён в разделе API.

Перед обходом GitLab фиксирует SHA коммита. Синхронизация заменяет весь источник:
источники репозиториев и документов должны различаться. Поддерживаемые текстовые
расширения перечислены в `src/agentai/adapters/gitlab.py`. Служебные папки пропускаются. Файлы более
512 КБ не индексируются, но ответ GitLab скачивается до проверки размера.

Примеры вопросов:

```text
Найди реализацию расчёта отчёта и укажи commit, путь и строки.
Проверь source-bundle.md: предложи доработку метода и законченные тесты.
Проанализируй OPTIMIZATION_DEMO_ORDERS и объясни применение min_total.
```

Явное имя файла или идентификатор с подчёркиваниями сужает поиск к найденному
документу в рамках текущего вопроса. Инструментальные шаги этого ответа сохраняют
выбранную область; новая тема в следующем сообщении снова ищется по всему
разрешённому корпусу. Общий поиск может возвращать посторонние фрагменты.

Учебный проект `examples/optimization-demo` использует словари, точные числа
`Decimal` и одну сортировку. Равные итоги сохраняют порядок первого появления
клиента в заказах. `min_total=None` сохраняет отрицательные возвраты; явный
порог применяется к итогам включительно.

```powershell
python -m unittest discover -s examples/optimization-demo -v
python scripts/documents.py --env .env upload examples/optimization-demo/source-bundle.md --source docs-demo
```

При остановке модели по длине API возвращает `finish_reason=length` и текстовое
предупреждение. Запрашивайте один файл или метод за раз. Увеличение лимита
не гарантирует правильность кода: проверяйте изменения тестами.

## Источники, версии и хранение

Фрагменты имеют размер до 50 строк и приблизительно 3500 символов. Форматы ссылок:

```text
gitlab:project@sha/path#Lstart-Lend
document:source/name@version?page=N#Lstart-Lend
document:source/name@version?paragraph=N#Lstart-Lend
document:source/name@version?table=N&row=N#Lstart-Lend
```

Номера строк документов относятся к извлечённому тексту. В Markdown с
пронумерованным кодом различайте строки документа и номера исходного файла.

| Данные | Хранение |
| --- | --- |
| Оригиналы | Том `documents`, путь `/app/data/documents` в API |
| Каталог, диалоги, задания и активные поколения | Том `postgres` |
| Текст, векторы и ссылки | Том `qdrant` |
| Настройки и данные WebUI | Том `webui` |

Архив хранит исходные байты, пользователя загрузки, время UTC, размер, SHA256
и состояние: `pending`, `indexed`, `superseded` или `failed`. При ошибке
индексации оригинал остаётся. Снятие с поиска отмечается состоянием `removed`.
Это отдельно от актуальности (`current`, `obsolete`, `draft`).
Старые версии можно скачать, но поиск использует
текущий индекс. Загрузка заменяет только соответствующий `document_id`.

Поколения переключаются через PostgreSQL после успешной
подготовки. Используйте один процесс и одну реплику API.

Перед ответом сервер обязательно выполняет поиск с проверкой прав. Сбой
начального поиска даёт 503. Навыки и последний непустой результат поиска
сохраняются между шагами. Начальный поиск выполняется дополнительно к
шагам генерации, ограниченным `MAX_STEPS`. Семантический отбор документов
делает дополнительные вызовы той же модели вне этого лимита.

Короткое точное совпадение с отдельной строкой заголовка возвращает исходный
фрагмент без пересказа. Регистр и пунктуация не учитываются. Это выдача
фрагмента, а не гарантия полноты документа. Переносы заголовка и дополнительные
слова в вопросе могут переводить запрос в обычный путь модели. Отдельно короткий
вопрос «Что такое …?» может получить точное наименование или описание из
структурированного источника без генерации. Это зависит от найденных доказательств.

## Права доступа

| Роль | Разрешения |
| --- | --- |
| `reader` | Общение, поиск, список и скачивание доступных документов |
| `indexer` | Загрузка и синхронизация разрешённых источников |
| `sql_reader` | Дополнительное чтение метаданных SQL; для общения нужна также `reader` |

Пользователь определяется ключом, хеш которого записан в `AGENT_USERS`.
Список `sources` ограничивает источники. Права проверяются до обеих ветвей
поиска, при загрузке и скачивании. Неизвестная или недоступная версия даёт 404.
Скачивание оригинала требует Bearer-заголовок: ссылка без авторизации не сработает.

Основной чат принимает личный API-ключ: сотрудники с разными ключами получают
свои права и историю. Старый WebUI использует общего пользователя `reader`:
сотрудники подключения имеют одинаковые источники. SSO и индивидуального
переноса прав WebUI пока нет.
Для разделения доступа используйте личные ключи API или отдельные подключения
и экземпляры под контролем администраторов. Ключ загрузчика нельзя использовать
как общий ключ WebUI.

Инструкции модели не предоставляют прав. Защита от инструкций внутри документов
опирается на ограничения инструментов; соблюдение всех правил моделью 4B
не гарантируется. Индексируйте только данные, предназначенные выбранной группе.

## Дополнительный SQL Server

Установите `.[sql]` и Microsoft ODBC Driver 18 в среде API: стандартный образ
их не содержит. Задайте `SQL_CONNECTION_STRING` с шифрованием и отдельной
учётной записью с разрешениями `CONNECT` и `VIEW DEFINITION`, без чтения
прикладных таблиц и записи. Назначайте `sql_reader` только нужным пользователям.

Инструмент выполняет постоянный запрос к `INFORMATION_SCHEMA.COLUMNS`:
не более 500 строк, тайм-аут 10 секунд. SQL от модели он не принимает.
Пустая строка подключения отключает SQL. Драйвер и права нужно проверить
в вашей среде: стандартные проверки контейнера их не подтверждают.

## Примеры запросов API

Примеры для WSL/bash. Задайте `READER_KEY` и `INDEXER_KEY` приватно в окружении;
не записывайте значения в Git и общие журналы.

```bash
curl -fsS http://localhost:8000/health

python -c 'import base64,json; print(json.dumps({"source":"docs-demo","filename":"source-bundle.md","content_base64":base64.b64encode(open("examples/optimization-demo/source-bundle.md","rb").read()).decode()}))' > upload.json
curl -fsS http://localhost:8000/ingest/document \
  -H "Authorization: Bearer $INDEXER_KEY" -H 'Content-Type: application/json' \
  --data-binary @upload.json

curl -fsS http://localhost:8000/ingest/gitlab \
  -H "Authorization: Bearer $INDEXER_KEY" -H 'Content-Type: application/json' \
  -d '{"source":"repo-demo"}'

curl -fsS http://localhost:8000/chat \
  -H "Authorization: Bearer $READER_KEY" -H 'Content-Type: application/json' \
  -d '{"question":"Как применяется min_total в source-bundle.md?"}'

curl -fsS http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer $READER_KEY" -H 'Content-Type: application/json' \
  -d '{"model":"local-agent","stream":false,"messages":[{"role":"user","content":"Объясни точку входа проекта со ссылками на код"}]}'
```

В PowerShell используйте `curl.exe`, JSON в файле и `--data-binary '@upload.json'`.
Для документов удобнее готовые скрипты.

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Проверка процесса без авторизации |
| `GET /ready` | Подробная готовность PostgreSQL, LM Studio, embeddings, Qdrant и настроенного OCR, роль `reader` |
| `GET /diagnostics/services` | Те же проверки с ошибками и подсказками по каждому сервису, роль `reader` |
| `GET /session` | Пользователь, роли и разрешённые источники |
| `GET /v1/models` | Модель интерфейса `local-agent` |
| `POST /v1/embeddings` | Векторы переданного текста через модель `EMBED_MODEL` |
| `POST /chat` | Вопрос и структурированный список источников |
| `POST /v1/chat/completions` | Совместимое с WebUI общение без потока |
| `POST /ingest/document` | Загрузка документа |
| `POST /ingest/gitlab` | Синхронизация репозитория |
| `GET /documents` | Версии доступных документов |
| `GET /documents/{version}/original` | Скачивание оригинала |

Перечисленные операции с данными требуют авторизацию; `/health` открыт.
Статические страницы, `/docs` и `/openapi.json` также доступны без ключа,
но не предоставляют доступ к документам или истории. Для `GET /documents`:
`limit` от 1 до 200, по умолчанию 50, и `offset`.

## API эмбеддингов

`POST /v1/embeddings` преобразует переданный текст в векторы через `EMBED_BASE_URL`
(в Compose — Qwen на CPU). При пустом адресе используется прежний LM Studio.
Этот универсальный маршрут не добавляет поисковую инструкцию автоматически;
встроенный поиск добавляет её только к вопросам, но не к документам.
Нужен Bearer-ключ пользователя с ролью `reader`. Маршрут не читает документы,
не записывает индекс и не требует работающего Qdrant или диалоговой модели.
Для поиска и индексации AgentAI продолжает использовать своё внутреннее подключение.

Пример для WSL/bash с ранее заданным `READER_KEY`:

```bash
curl -fsS http://localhost:8000/v1/embeddings \
  -H "Authorization: Bearer $READER_KEY" -H 'Content-Type: application/json' \
  -d '{"input":["Первый текст","Второй текст"],"encoding_format":"float"}'
```

Параметры запроса:

| Поле | Значение |
| --- | --- |
| `input` | Непустая строка или массив от 1 до 16 непустых строк |
| `model` | Необязательно; допускается только точное значение `EMBED_MODEL` |
| `encoding_format` | `float` по умолчанию или `base64` — Float32 в порядке little-endian |

Лимиты: до 8192 символов на текст и 32768 символов на пакет. Они не заменяют
ограничение контекста модели: embedding-сервис может отклонить более короткий текст
по числу токенов. Массивы токенов и параметр `dimensions` не поддерживаются.
В `/v1/models` по-прежнему публикуется только диалоговая модель `local-agent`,
чтобы WebUI не предлагал модель эмбеддингов для общения.

Ответ содержит `object: "list"`, фактическую настроенную модель, массив `data`
с `index` и `embedding`, а также `usage` от embedding-сервиса. Порядок соответствует
входным текстам. Размерность определяется моделью, а не фиксируется в API.
Сервис может вернуть нулевые счётчики `usage`; API передаёт их без оценки
числа токенов со своей стороны.

Ошибки: 401 — неизвестный ключ, 403 — нет роли, 400 — другая модель,
422 — неверный ввод или его отклонение embedding-сервисом, 429 — занята общая операция,
503 — недоступный сервер или некорректный ответ. Секреты и тексты ошибок
сервиса клиенту не передаются. Вызов не меняет модель существующего индекса;
при смене `EMBED_MODEL` нужна переиндексация базы знаний.

документы — documents. Дополнительный навык можно загрузить через `load_skill`.

## Тесты и критерии приёмки

Для локальной среды Python 3.11+:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[test]"
python scripts/test.py
python scripts/verify_static.py
python scripts/architecture_check.py
python -m unittest discover -s examples/optimization-demo -v
```

В WSL активация: `source .venv/bin/activate`. Выполняйте команды из корня проекта.
Автономные тесты используют Qdrant в памяти и подставные модели; GPU и LM Studio
им не нужны. Для полного набора требуется отдельная PostgreSQL через
`TEST_DATABASE_URL`; без неё соответствующие тесты пропускаются. Живые оценки
поиска и ответов требуют работающих моделей. Последний полный backend-прогон:
**229 passed**; отдельная синтетическая оценка поиска: **38/38**. Область и
ограничения проверок описаны в [актуальном отчёте](docs/natural-retrieval-fix.md).

Критерии приёмки:

- Тесты проходят; неизвестный ключ даёт 401, неверная роль или источник — 403.
- После загрузки `source-bundle.md` ответ о `min_total` соответствует исходнику
  и содержит проверенную ссылку.
- Ссылки PDF и DOCX соответствуют страницам, абзацам и строкам таблиц оригиналов.
- Код цитируется с SHA, путём и строками; повторная синхронизация заменяет индекс.
- Пользователи с разными источниками не получают чужие тексты и ссылки.
- Агент останавливается по `MAX_STEPS`, занятая параллельная операция даёт 429.
- Запрос по имени файла не содержит посторонних источников, обрыв помечается явно.
- Основной чат получает ответ через AgentAI и сохраняет диалог; новая тема
  не ограничивается источниками предыдущего вопроса.
- На целевом компьютере измерены RAM/VRAM, задержки и поведение при нехватке памяти.
- Для SQL отдельно проверены права и отсутствие чтения прикладных таблиц или записи.

Реально выполненные проверки перечислены в [документации](docs/README.md). Список критериев
не означает, что все они проверены в вашей среде.

## Обновление и резервное копирование

После изменения кода:

```powershell
docker compose up -d --build api
```

После изменения `.env` пересоздайте нужные сервисы. Если изменился ключ WebUI,
обновите также сохранённый ключ подключения. Теги образов заданы в Compose,
зависимости зафиксированы в `uv.lock` и `requirements.lock`. Docker устанавливает
`requirements.lock`. Для согласованного обновления:

```powershell
uv lock
uv export --no-dev --no-hashes --no-emit-project --output-file requirements.lock
```

Перезапуск сохраняет тома. **`docker compose down -v` удаляет тома с базой знаний
и данными WebUI.** Сохраняйте `documents`, `postgres` и `qdrant`; при использовании старого
WebUI сохраняйте также `webui`.
Остановите API и загрузку на время согласованной копии; PostgreSQL сохраняйте
через pg_dump либо согласованную копию остановленной БД.

При смене модели эмбеддингов или её версии переиндексируйте все источники,
даже если размерность совпала. При смене размерности создайте отдельную коллекцию,
изменив `Store.collection` в `src/agentai/knowledge/store.py`; старую сохраняйте до проверки нового
индекса. Переменная окружения для имени коллекции пока не предусмотрена.

При миграции с Ollama замените настройки на `LMSTUDIO_*` из шаблона. Старые
сервисы останавливайте после проверки. Документы, загруженные до появления
архива оригиналов, загрузите заново. Старые фрагменты без `document_id` сами
не удаляются: используйте новый источник/коллекцию или отдельно очистите индекс.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Нет модели в WebUI, Network Problem | Работу API, адрес `http://api:8000/v1`, сохранённый ключ |
| 401 | Bearer-ключ и соответствие его SHA256 записи пользователя |
| 403 | Роль и наличие источника в `sources` |
| 503 при авторизации | Корректность JSON-массива `AGENT_USERS` |
| Обращения к порту Ollama 11434 | Отключение Ollama в сохранённых настройках WebUI |
| 503 при поиске | Qdrant, сервис embeddings и его модель; для генерации — LM Studio |
| Ошибка генерации | Адрес, авторизацию, загрузку модели, поддержку инструментов и контекст |
| Документ не найден | Успех индексации, доступ к источнику, активную версию, текстовый слой или работу OCR |
| Ответ повторяет предыдущую тему | Обновление API, текущий вопрос и `conversation_id`; проверку нескольких тем из инструкции RAG |
| Источник найден, но ответ отрицает его содержание | `validation`, `retrieval` и точный процитированный фрагмент; проверки не охватывают все смысловые ошибки |
| Ответ с кодом оборван | Предупреждение о длине; запросите меньшую часть задачи |

Журнал API: `docker compose logs --tail 50 api`. Перед передачей журналов удаляйте
секреты и закрытые данные. `/ready` проверяет PostgreSQL, идентификаторы моделей, Qdrant и доступность OCR,
но не подтверждает загрузку, успешную генерацию и достаточность памяти.

## Ограничения MVP

- Клиентские системные сообщения игнорируются; для продолжения диалога нужен
  conversation_id или идентификатор WebUI, описанный выше.
- Только текстовые ответы без потока.
- BM25 и корпус кешируются с учётом прав и активных поколений. Дополнительный
  семантический отбор ограничен каталогом из 48 документов; поиск и задержка
  на больших базах требуют отдельных измерений.
- Нужен один процесс API; переключение поколений в PostgreSQL атомарно,
  хранение оригиналов и векторов не является распределённой транзакцией.
- OCR работает отдельным локальным сервисом; сложные таблицы и ошибки распознавания
  требуют проверки. Нет удаления оригиналов по срокам хранения, согласования
  документов и полного аудита. Простая библиотека доступна по /library.
- Нет SSO и индивидуального переноса прав WebUI.
- Нет MCP, исполнения кода, клонирования, push и применения патчей агентом.
- Тесты на примерах не гарантируют корректность всех ответов модели.
