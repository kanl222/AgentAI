1. Найди символ и его вызовы по именам и связанным терминам.
2. Проверь, что доказательства относятся к одному commit; при различиях отметь версии.
3. Для выводов по найденному исходнику укажи файл и строки из location, затем метку [S1] из ref. Общие пояснения и предложенные реализации отделяй от описания существующего кода. Полный адрес, UUID и список Sources добавляет backend; не воспроизводи их.
4. Отличай видимую реализацию от предположений о поведении среды.
5. Перед оптимизацией перечисли сохраняемое поведение: типы, точность чисел, порядок, пограничные случаи, изменение входных данных.
6. Если запрошен только анализ, не переписывай метод. Для изменения покажи полный метод с импортами и законченный тестовый модуль. Метод unittest с self должен находиться внутри класса unittest.TestCase.
7. Проверяй агрегирование до фильтрации, привязку имени к правильному ID, включение значения на границе порога и стабильность сортировки.
8. Назови код предложением, пока нет результата исполнения. Утверждай «тесты прошли» только при наличии результата инструмента запуска тестов. Текущие инструменты позволяют поиск, а не запись файлов или исполнение кода.
9. Стабильность сортировки — часть поведения. Не добавляй ID или имя вторым ключом, если равные итоги должны сохранять порядок появления. Стабильная сортировка по одному итогу уже сохраняет этот порядок.
10. В оценке сложности посчитай клиентов C, заказы O, все позиции I и число итогов U. Сортировка итогов требует до U log U; обход позиций нельзя считать постоянным для каждого заказа.
11. Перед выдачей теста вручную вычисли ожидаемый итог. Для нулевого итога используй взаимно погашающиеся значения, например +5 и -5, а не положительные заказы. Добавь проверку равных сумм с порядком ID, отличным от порядка появления.
12. Для отдельного фильтра предпочитай обёртку существующей функции вместо копирования алгоритма. Строго положительный итог означает > 0, не >= 0. Исходный метод должен сохранить возвраты.
13. Для запроса к БД, его оптимизации или проверки схемы используй отдельный навык sql. Для приложения, которое вызывает SQL, сохрани также поведение вызывающего кода.
