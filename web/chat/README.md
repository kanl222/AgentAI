# AgentAI Chat

Самостоятельное приложение на Node.js 24. HTTP-сервер и прокси — `server.mjs`, запуск и корректное завершение — `start.mjs`. Интерфейс находится в `public/`: `index.html`, `chat.js`, `chat-render.js`, `chat.css`. Подсветка — локальный Highlight.js 11.12.0; в браузере нет обращений к CDN.

Сборка: `docker compose up -d --build chat` из корня проекта. Адрес: http://localhost:3000/. API находится за `/api/`. Адрес сервера задаётся переменной `AGENTAI_URL` (в Docker — `http://api:8000`, вне Docker — `http://127.0.0.1:8000`). Указывайте origin без `/v1`, путей и ключей.

Локальный запуск без Docker (Node.js 24 должен быть установлен):

```powershell
cd D:\Source\AgentAI\web\chat
npm ci
npm start
# либо с перезапуском после изменения серверного кода
npm run dev
```

`npm ci` устанавливает закреплённый пакет подсветки; скрипт `build:assets` копирует в `public/vendor/` только ядро, выбранные языки и лицензию. Он автоматически запускается перед `start`, `dev` и `test`. HTTP-сервер использует стандартные модули Node.js. Backend AgentAI и его базы должны работать отдельно. По умолчанию Node слушает `127.0.0.1:3000`; `HOST` и `PORT` можно изменить через окружение. Ключ доступа вводится в браузере, сервер чата не читает корневой .env.

Проверка: `npm test`. Интеграционные тесты создают временный backend на случайном локальном порту: статические файлы, авторизация, JSON, PDF без повреждения байтов, ограничения размера, таймауты, параллельность и отключение клиента. Docker-сборка сначала выполняет эти тесты, затем создаёт образ без тестовых файлов, с пользователем `node` и проверкой `/health`.

`/health` показывает состояние Node-сервера. Готовность модели и AgentAI проверяется авторизованным `/api/ready`. Старый адрес `/error` перенаправляется на главную страницу чата.

Возможности: история и поиск диалогов, очередь ответов, восстановление наблюдения за заданиями после подключения, SQL и таблицы, копирование ответа/кода, фрагменты источников и скачивание оригиналов, список документов. Для загрузки и администрирования документов есть ссылка на отдельную консоль.

Кнопка солнца/луны в шапке переключает тему. При первом открытии учитывается системная тема; явный выбор сохраняется в localStorage и синхронизируется между вкладками. Известные языки fenced-блоков подсвечиваются, неизвестные и блоки без языка остаются текстом. Копирование возвращает исходный код без разметки.

Подключение сохраняется на 30 дней: Node проверяет ключ через AgentAI и выдаёт
зашифрованную AES-256-GCM cookie с HttpOnly и SameSite=Strict. Исходный ключ не
возвращается JavaScript и не записывается в localStorage. При восстановлении и
каждом API-запросе действуют серверные права; отозванный ключ перестаёт работать.
«Выйти на этом устройстве» очищает cookie и локальное состояние текущего пользователя.

Выбранный диалог, его черновик и положение списка сохраняются локально с отдельной
областью для каждого ключа. Тексты ответов читаются с сервера. Диалоги сгруппированы
по датам, у каждого есть время обновления; записи «Новый диалог» собраны в раскрываемый
раздел «Без названия», а не удалены. История и документы принадлежат backend:
последние 40 пар вопрос/ответ с учётом серверного срока хранения. Смена диалога
не останавливает задание, после перезагрузки наблюдение за ним возобновляется.
Отменить можно только запрос в очереди. Потоковой выдачи API пока нет.

Ключ шифрования сессии создаётся автоматически с правами 0600. В Compose он
хранится в томе `chat-sessions` по `/app/data/session.key`; вне Docker —
`data/chat-session.key` в корне проекта. Путь можно задать через
`CHAT_SESSION_KEY_FILE`. Том нужен для сохранения входа при пересоздании контейнера.
Удаление ключа завершает сохранённые подключения; историю диалогов не удаляет.
Интерфейс рассчитан на локальный HTTP-запуск, доступный только на `127.0.0.1`.

## Вложения к сообщениям

Кнопка со скрепкой рядом с полем ввода прикрепляет до трёх файлов общим размером до 15 МБ. Можно отправить файл без текста — AgentAI кратко опишет его содержимое. Перед отправкой вложение можно убрать.

Поддерживаются PDF, DOCX, TXT, Markdown, текстовые файлы с кодом и изображения PNG/JPEG/WebP/TIFF. Текстовые файлы должны быть в UTF-8; для сканов и изображений нужен настроенный OCR. При ошибке чтения сообщение об ошибке появляется в диалоге. Максимальный объём извлечённого текста всех вложений — 400 000 символов; большие документы следует разделить.

Поиск для такого сообщения ограничивается вложениями. Они не публикуются в общей библиотеке и не требуют роли `indexer`: достаточно `reader`. В истории этого диалога хранятся названия и извлечённые фрагменты, исходные двоичные файлы в архив документов не добавляются. Запросы вида «Что ещё в этом файле?» повторно используют вложение предыдущего ответа. Новый самостоятельный вопрос без вложения возвращается к поиску по общей базе. Несохранённые вложения очищаются при переходе в другой диалог, выходе и обновлении страницы.

API `/chat` и `/jobs/chat` принимают поле `attachments`: массив объектов с `filename` и `content_base64`. Содержимое файлов считается данными, а не инструкциями модели. Как и остальные сообщения, вложения доступны владельцу диалога и удаляются вместе с ним в рамках срока хранения истории. Задания очереди также содержат исходное вложение в своём payload и подчиняются правилам хранения заданий.
