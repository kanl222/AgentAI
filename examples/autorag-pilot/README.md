# Пробный стенд AutoRAG Legacy

Отдельный эксперимент поиска на локальном снимке корпуса AgentAI. Зависимости
основного приложения, рабочая БД и индекс не меняются. Все данные и результаты
располагаются в исключённом из Git каталоге `work/autorag-pilot/`.

## Окружение

Python 3.11. Из корня проекта в PowerShell:

```powershell
python -m venv work/autorag-pilot/.venv
uv --cache-dir .uv-cache pip install --python work/autorag-pilot/.venv/Scripts/python.exe -r examples/autorag-pilot/requirements.txt
work/autorag-pilot/.venv/Scripts/python.exe scripts/autorag_pilot.py --run
```

Команда `python` при создании окружения должна указывать на Python 3.11.
Установка требует доступа к PyPI. Эксперимент не загружает `.env`, не обращается
к облачным моделям и не использует секреты проекта.

## Данные и проверка

Нужны сохранённые файлы предыдущей проверки:

- `work/evaluation-20261022-corpus.json`;
- `work/evaluation-20261022-natural.json`;
- `work/evaluation-20261022-extra.json`.

Их содержимое не включается в репозиторий. Снимок содержит 96 фрагментов из 32
документов. В скрипте зафиксированы 18 вопросов с разметкой нужных фрагментов:
10 для настройки, 8 для контроля. Целевые документы между группами не
пересекаются; это проверяется перед запуском. Полный корпус одинаков и доступен
поиску в обеих группах, контрольные метки не участвуют в выборе варианта.

AutoRAG запускает три варианта BM25: стандартный `space`, текущие лексические
признаки AgentAI и русский Snowball. Два дополнительных обработчика
регистрируются только в памяти процесса эксперимента. Фрагменты, модель и
рабочий поиск AgentAI не меняются. Размер выдачи всегда 6.

Выбор производится по MRR@6 на группе настройки; при равенстве учитывается число
вопросов со всеми необходимыми фрагментами. На контрольной группе запускается
только выбранный вариант. Группы эталонов учитывают обязательные части ответа;
внутри группы допускаются альтернативные фрагменты. Для нескольких обязательных
групп MRR усредняется по группам, как в AutoRAG 0.3.27.

Сравнение с AgentAI использует сохранённую начальную выдачу от 22 октября,
без каталога, дочитывания страниц и генерации. Это не свежая проверка сервиса
и не сравнение качества готовых ответов. Генерация не оценивается:
`generation_gt` намеренно пуст. Два вопроса без ответа исключены из метрик
поиска и отмечены в manifest.json. Набор мал; результаты не доказывают общую
точность системы и не служат основанием для автоматического внедрения.

## Результаты

- `manifest.json` — состав набора и SHA-256 снимка;
- `qa-development.parquet`, `qa-holdout.parquet`, `corpus.parquet` — вход AutoRAG;
- `trials/` — исходные результаты и таблицы AutoRAG;
- `selected.json` — выбранная конфигурация до контрольного запуска;
- `results.json` — метрики и результаты каждого вопроса.

Первый опыт описан в [отчёте](../../docs/autorag-pilot-20261022.md). Полный список
версий установленного окружения сохранён локально в `requirements.freeze.txt`.
В ограниченной песочнице Windows asyncio может зависать при создании служебного
loopback-соединения; первый успешный запуск выполнен с разрешением на локальное
соединение. Дополнительные GPU-пакеты для этого опыта не нужны.
Без PyTorch при выходе возможен `ModuleNotFoundError: torch` из необязательного
обработчика очистки `VllmEmbedding.close` в AutoRAG. В повторном запуске код
завершения был 0, результаты всех испытаний записались и совпали с отчётом.

Повторный запуск добавляет новый номер испытания AutoRAG. Для другого снимка
используйте новый каталог через `--output`, чтобы AutoRAG не переиспользовал
прежние файлы корпуса и BM25.
